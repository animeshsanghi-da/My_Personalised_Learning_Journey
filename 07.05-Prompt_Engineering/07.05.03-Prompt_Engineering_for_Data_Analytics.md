# Prompt Engineering for Data Analytics: Practical Applications

## Introduction
As a Data Analyst, your primary tools are Python, SQL (MySQL), and BI platforms like Tableau. Integrating Large Language Models (LLMs) into your workflow does not replace these tools; it supercharges them. This module focuses on crafting highly specific prompts to solve real-world data engineering problems, directly applicable to your healthcare ETL projects, your local XAMPP environment, and your daily analytics tasks.

## 1. Generating Complex MySQL Queries

When writing ETL scripts (like your phase-based healthcare data processing algorithm), you often need complex SQL queries involving `JOIN`s, `GROUP BY` clauses, and window functions. LLMs can write these instantly, but *only* if you provide the correct database schema and constraints.

### The "Schema-First" Approach
Never ask an LLM to "write a query to get patient data." Always provide the table structure first.

**Poor Prompt:**
> Write a MySQL query to find the average wait time for patients in Phase 2 of the healthcare pipeline.

**Professional Prompt:**
> Act as an expert Data Engineer. I am working on a healthcare ETL pipeline using MySQL in a local XAMPP environment.
> 
> Here is my schema:
> Table: `patient_processing`
> Columns: `patient_id` (INT), `intake_time` (DATETIME), `phase_2_start` (DATETIME), `department` (VARCHAR)
> 
> Task: Write a MySQL query to calculate the average wait time (in minutes) between `intake_time` and `phase_2_start`, grouped by `department`. 
> Constraint: Only include patients where `phase_2_start` is not NULL. Optimise for execution speed.

*Why this works:* It provides the exact schema, defines the output metric (minutes), and sets handling for missing data (NULLs).

``` sql
-- Expected LLM Output:
SELECT 
    department,
    AVG(TIMESTAMPDIFF(MINUTE, intake_time, phase_2_start)) AS avg_wait_time_minutes
FROM 
    patient_processing
WHERE 
    phase_2_start IS NOT NULL
GROUP BY 
    department;
```

## 2. Debugging Python and Pandas Code

When your Python ETL scripts fail in VS Code or Jupyter Lab, LLMs are exceptional debugging assistants. The key is to provide the error traceback and a reproducible sample of your DataFrame.

### The "Traceback + Context" Framework

**Poor Prompt:**
> My Pandas merge is failing with a KeyError. Fix it.
> ``` python
> df_merged = pd.merge(df_patients, df_treatments, on='PatientID')
> ```

**Professional Prompt:**
> I am doing data manipulation in Python using Pandas. I am trying to merge two dataframes, but I am getting a `KeyError: 'PatientID'`.
>
> Here is the structure of my first dataframe `df_patients`:
> Columns: ['patient_id', 'name', 'age']
> 
> Here is the structure of my second dataframe `df_treatments`:
> Columns: ['PatientID', 'treatment_code', 'cost']
>
> Here is my code:
> ``` python
> df_merged = pd.merge(df_patients, df_treatments, on='PatientID')
> ```
>
> Please identify the error and provide the corrected code to perform an inner join.

*Why this works:* You provided the column names. The LLM will immediately spot the case sensitivity/naming mismatch (`patient_id` vs `PatientID`) and suggest `left_on` and `right_on` parameters.

## 3. Interpreting Massive Datasets

You cannot paste 100,000+ rows (like the Olist E-commerce dataset) into an LLM. Instead, you must use Prompt Engineering to help you *Analyse* the metadata and generate statistical code.

### The "Data Dictionary" Prompt
Provide the LLM with the `.info()` or `.describe()` output, not the raw data.

**Example Prompt:**
> Act as a Senior Business Intelligence Analyst. I am analysing an e-commerce dataset to find reasons for a drop in Q3 sales. I cannot share the raw data, but here is the output of `df.info()`:
> 
> [Paste df.info() output here]
> 
> Based on these column names and data types, suggest 3 exploratory data analysis (EDA) questions I should ask to identify the root cause of the sales drop. For each question, provide the corresponding Python code using Pandas and Seaborn to visualise the answer.

## Summary
Effective Prompt Engineering in data analytics is about translating business context and structural metadata into instructions the LLM can understand. By mastering the Schema-First approach for MySQL and the Context Framework for Python, you will drastically reduce the time spent debugging and writing boilerplate code.
