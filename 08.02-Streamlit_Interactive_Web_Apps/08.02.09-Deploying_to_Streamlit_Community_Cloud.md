# Deploying to Streamlit Community Cloud

## Introduction

Building a dynamic Machine Learning dashboard or a data exploration tool on your local machine is only half the battle. To truly leverage these tools for stakeholder presentations or to showcase your analytical capabilities to recruiters, the application must be accessible via a public URL. 

Streamlit Community Cloud provides a free, seamless hosting platform that integrates directly with your GitHub repository. This module covers the final phase of your deployment lifecycle: packaging your environment, connecting your repository, and launching your web app live to the internet.

---

## 1. Managing Dependencies: The `requirements.txt` File

When you run an app locally in VS Code or Jupyter Lab, your machine already has Python, Pandas, Scikit-learn, and Streamlit installed. The Streamlit Community Cloud server, however, starts completely blank. You must explicitly tell the server which libraries to install using a `requirements.txt` file.

If this file is missing or incorrect, your deployment will immediately fail.

### Best Practice for Creating `requirements.txt`

Do not run `pip freeze > requirements.txt` in your base Anaconda environment. This will export hundreds of irrelevant packages, causing slow build times or conflicts. Instead, explicitly list only the libraries your app imports.

Create a file named `requirements.txt` in the root of your project directory and list your dependencies:

``` text
streamlit==1.32.0
pandas==2.2.0
numpy==1.26.4
scikit-learn==1.4.1.post1
matplotlib==3.8.3
seaborn==0.13.2
```

*Pro-Tip:* Always include version numbers. If an update to Scikit-learn deprecates a function you used in your prediction dashboard, your live app will break unless the version is locked.

## 2. Pushing the Project to GitHub

Streamlit Cloud pulls your code directly from a public or private GitHub repository. 

1. Ensure your project folder contains your main Python script (e.g., `app.py`), your `requirements.txt`, and any static datasets (like smaller CSV files). 
2. Note on Large Data: If you are working with large datasets, such as the 100,000+ row Olist E-commerce dataset, do **not** push the raw CSV to GitHub. GitHub has a strict file size limit (100MB). For massive datasets, you should fetch the data dynamically from a cloud database (like BigQuery) or a cloud storage bucket during runtime.
3. Commit and push your code to your repository. 

For example, your structure at `https://github.com/animeshsanghi-da/ML-Prediction-Dashboard` should look like this:

``` text
ML-Prediction-Dashboard/
│
├── app.py                 # The main Streamlit application script
├── requirements.txt       # Your dependency list
├── helper_functions.py    # Any custom ETL or algorithm scripts
└── .gitignore             # Ignoring __pycache__ and local environments
```

## 3. Deploying via Streamlit Community Cloud

Once your code is safely on GitHub, the deployment process is highly automated.

1. Navigate to [share.streamlit.io](https://share.streamlit.io/) and log in using your GitHub account credentials.
2. Click the **"New app"** button.
3. Grant Streamlit access to your GitHub repositories if prompted.
4. Fill in the deployment form:
   * **Repository:** Select your repository from the dropdown (e.g., `animeshsanghi-da/ML-Prediction-Dashboard`).
   * **Branch:** `main` (or whichever branch holds your production code).
   * **Main file path:** `app.py` (the script containing your `st.set_page_config` and UI layouts).
   * **App URL:** You can customize the URL to make it professional (e.g., `animesh-da-prediction-dashboard.streamlit.app`).
5. Click **Deploy!**

You will see an interactive terminal on the right side of the screen displaying the build logs. It will read your `requirements.txt`, install the necessary libraries, and launch the app.

## 4. Handling Sensitive Data (Secrets Management)

If your application connects to a MySQL database, queries a cloud data warehouse, or uses an external API, you **must never** hardcode your passwords or API keys directly into your GitHub scripts. 

Streamlit provides a secure way to handle this via **Secrets**.

### Local Testing
Create a folder named `.streamlit` in your project root, and inside it, create a file named `secrets.toml`:

``` toml
# .streamlit/secrets.toml
[mysql]
host = "localhost"
port = 3306
database = "healthcare_etl_db"
user = "root"
password = "MySuperSecretPassword123"
```

*Crucial:* Ensure `.streamlit/secrets.toml` is added to your `.gitignore` file so it is never pushed to GitHub.

### Accessing Secrets in Python
Inside your `app.py`, you can securely call these credentials:

``` python
import streamlit as st
import mysql.connector

# Securely fetching the password from secrets
db_password = st.secrets["mysql"]["password"]

def init_connection():
    return mysql.connector.connect(
        host=st.secrets["mysql"]["host"],
        user=st.secrets["mysql"]["user"],
        password=db_password,
        database=st.secrets["mysql"]["database"]
    )
```

### Configuring Secrets in the Cloud
Since your local `secrets.toml` is not on GitHub, the live app will fail unless you configure the secrets in the cloud environment.
1. Go to your deployed app on Streamlit Cloud.
2. Click the three dots (⋮) in the bottom right corner and select **Settings**.
3. Navigate to the **Secrets** tab.
4. Paste the contents of your local `secrets.toml` file directly into the text box and save.

Your app can now securely connect to your databases without exposing credentials in your public repository.

## 5. Maintenance and App Hibernation

Streamlit Community Cloud is a free service. If your app receives no web traffic for 7 consecutive days, it will automatically go into **hibernation** to save server resources. 

* Visitors will see a "This app is sleeping" screen.
* Anyone (not just you) can click the "Wake up" button to reactivate it, though it will take a minute or two to rebuild the environment. 
* To prevent hibernation entirely during peak job search periods, simply visit your app's URL once every few days to keep the server instance active and instantly accessible for anyone reviewing your portfolio visualisations.
