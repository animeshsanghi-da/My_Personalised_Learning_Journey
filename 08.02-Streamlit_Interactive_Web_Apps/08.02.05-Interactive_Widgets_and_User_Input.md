# Streamlit Interactive Widgets and User Input

## Introduction
The true power of Streamlit lies in its ability to transform a static data analysis script into an interactive application. For a Data Analyst or Business Intelligence professional, this means stakeholders can explore the data themselves without needing to read your Python code. 

By adding interactive widgets (like sliders, dropdowns, and date pickers), you allow users to dynamically filter datasets—such as an e-commerce database—and update visualisations in real-time.

---

## The Golden Rule of Streamlit Widgets
In Streamlit, **widgets are just variables**. 

When a user interacts with a widget on the web page, Streamlit automatically reruns the Python script from top to bottom, updating the variable assigned to that widget. There is no need to write complex event listeners or callback functions like you would in traditional web development.

---

## 1. Number and Range Inputs: Sliders
Sliders are perfect for filtering continuous numerical data, such as order values, freight distances, or customer review scores.

### `st.slider()`
You can use a slider to select a single value or a range of values.

``` python
import streamlit as st
import pandas as pd

st.subheader("Filter E-Commerce Orders")

# Single value slider
min_review_score = st.slider(
    label="Minimum Customer Review Score",
    min_value=1,
    max_value=5,
    value=3,  # Default value
    step=1
)

# Range slider (returns a tuple)
price_range = st.slider(
    label="Select Order Price Range (BRL)",
    min_value=0.0,
    max_value=1500.0,
    value=(50.0, 300.0) # Default range
)

st.write(f"Showing orders with a score of at least {min_review_score} and prices between {price_range[0]} and {price_range[1]}.")
```

## 2. Categorical Inputs: Dropdowns and Multiselects
When analysing categorical data (e.g., product categories, customer states, payment methods), you need to restrict user input to specific predefined options.

### `st.selectbox()` (Single Choice)
Creates a dropdown menu where the user can select only one option.

``` python
# Simulating unique states from a customer dataset
brazilian_states = ['SP', 'RJ', 'MG', 'RS', 'PR']

selected_state = st.selectbox(
    label="Select Customer State to Analyse:",
    options=brazilian_states,
    index=0 # Defaults to 'SP'
)

st.write(f"Currently analysing logistics for: {selected_state}")
```

### `st.multiselect()` (Multiple Choices)
Allows the user to select multiple options, returning them as a Python list. This is highly useful for comparing different segments side-by-side in a visualisation.

``` python
product_categories = ['health_beauty', 'sports_leisure', 'furniture_decor', 'computers_accessories']

selected_categories = st.multiselect(
    label="Compare Product Categories:",
    options=product_categories,
    default=['health_beauty', 'sports_leisure'] # Pre-selected options
)

# The resulting variable is a list, perfect for Pandas filtering:
# filtered_df = df[df['product_category_name'].isin(selected_categories)]
```

## 3. Time Series Inputs: Date Pickers
Time-series analysis is foundational for business intelligence. Forecasting sales, tracking seasonal trends, or analysing cohort retention requires precise date filtering.

### `st.date_input()`
Allows the user to select a single date or a date range via a calendar UI.

``` python
import datetime

st.subheader("Analyse Q3 Sales Performance")

# Date range selection
date_range = st.date_input(
    label="Select Order Date Range:",
    value=(datetime.date(2018, 1, 1), datetime.date(2018, 12, 31)),
    min_value=datetime.date(2016, 1, 1),
    max_value=datetime.date(2018, 12, 31)
)

# Error handling: Ensure the user selected a full range (start and end date)
if len(date_range) == 2:
    start_date, end_date = date_range
    st.success(f"Analysing data from {start_date} to {end_date}.")
else:
    st.warning("Please select an end date to continue.")
```

## 4. Ingesting New Data: The File Uploader
For internal business tools, stakeholders often need to upload their own `.csv` or `.xlsx` files for immediate analysis. 

### `st.file_uploader()`
Creates a drag-and-drop zone for file uploads. The uploaded file is held in memory and can be passed directly into Pandas.

``` python
st.subheader("Upload Monthly Extract")

# Restrict uploads to specific file types
uploaded_file = st.file_uploader(
    label="Upload your CSV file here:",
    type=['csv']
)

if uploaded_file is not None:
    # Read the file directly into a Pandas DataFrame
    custom_df = pd.read_csv(uploaded_file)
    st.write("Data successfully loaded! Previewing the first 5 rows:")
    st.dataframe(custom_df.head())
```

## 5. Execution Control: Buttons
Because Streamlit reruns the script upon *every* widget interaction, computationally heavy tasks (like running a Machine Learning model or executing a complex SQL CTE against a massive dataset) shouldn't trigger automatically. You want to gate these actions behind a button.

### `st.button()`
Returns `True` only in the exact execution cycle that it was clicked.

``` python
st.write("Ready to process the predictive model?")

# The block inside this 'if' statement only runs when the button is clicked
if st.button(label="Execute Predictive Model"):
    with st.spinner("Processing data..."):
        # Insert heavy computation here
        import time
        time.sleep(2) # Simulating processing time
    
    st.success("Model executed successfully!")
    st.balloons() # A fun visual reward built into Streamlit
```

---

## Summary of Best Practices
1. **Always provide sensible defaults:** Your dashboard shouldn't be empty when it first loads. Give sliders and dropdowns logical default `value` parameters.
2. **Filter via Pandas instantly:** Pass the variables generated by these widgets directly into Pandas boolean masks (e.g., `df[df['price'] < max_price]`) before generating your visualisations.
3. **Use buttons for heavy lifting:** Never trigger a 3-minute database query just because a user clicked a single dropdown menu. Gate heavy operations behind `st.button()`.
