# Streamlit: Advanced Caching and Session State

## Introduction
One of the most surprising things for analysts transitioning from Jupyter Notebooks to Streamlit is Streamlit's execution model: **every time a user interacts with a widget, the entire Python script reruns from top to bottom.** If you are building a dashboard for your 100,000+ row Olist E-Commerce dataset or a complex Scikit-learn predictive model, reloading that data on every button click will make your app frustratingly slow and crash your server. To build enterprise-grade, performant web apps, you must master **Caching** and **Session State**.

---

## 1. The Power of Caching: `@st.cache_data`

The `@st.cache_data` decorator is used to cache functions that return data (like Pandas DataFrames, lists, or API responses). When Streamlit sees this decorator, it checks if the function has been run with the exact same inputs before. If yes, it skips the computation and instantly returns the saved data.

### Use Case: Loading Large Datasets (Olist E-Commerce)
Without caching, querying 100k rows takes seconds *every* time a user changes a filter. With caching, it takes seconds *once*.

```python
import streamlit as st
import pandas as pd

# The decorator tells Streamlit to cache the output of this function
@st.cache_data
def load_olist_data():
    # Imagine this is a heavy operation, like reading a massive CSV or querying a database
    df = pd.read_csv("olist_orders_dataset.csv")
    
    # Perform heavy data cleaning here so it only happens once
    df['order_purchase_timestamp'] = pd.to_datetime(df['order_purchase_timestamp'])
    return df

st.title("Olist E-Commerce Dashboard")

# This will take time on the first load, but will be instant on subsequent reruns!
data = load_olist_data()
st.write(f"Successfully loaded {len(data)} rows.")

# Even when the user interacts with this slider (causing a script rerun), 
# the data does NOT reload from disk.
sample_size = st.slider("Select sample size to analyse:", 100, 1000, 500)
st.dataframe(data.sample(sample_size))
```

*Pro-Tip:* You can set an expiration time using `@st.cache_data(ttl=3600)` to force the app to fetch fresh data every hour—perfect for live business metrics.

## 2. Managing Connections: `@st.cache_resource`

While `cache_data` is for data that can be serialized, `@st.cache_resource` is for global resources like **Database Connections** or **Machine Learning Models**. You do not want to open a new connection to your MySQL database every time a user clicks a button (as you know from your Healthcare ETL project).

### Use Case: Database Connections & ML Models

```python
import streamlit as st
import mysql.connector
import joblib

# Cache the database connection so it remains open across reruns
@st.cache_resource
def init_db_connection():
    return mysql.connector.connect(
        host="localhost",
        user="root",
        password="password",
        database="healthcare_db"
    )

# Cache your trained Scikit-learn model so it only loads into memory once
@st.cache_resource
def load_ml_model():
    return joblib.load("linear_regression_model.pkl")

conn = init_db_connection()
model = load_ml_model()

st.success("Database connected and ML Model loaded efficiently!")
```

## 3. Preserving User Memory: `st.session_state`

Because Streamlit reruns the script on every interaction, it is inherently **stateless**. It forgets everything that happened in the previous run. If you want to build a multi-step form, a pagination system, or a shopping cart, you must use `st.session_state`.

`st.session_state` is a Python dictionary that persists across reruns for a specific user session.

### Use Case: Keeping Track of Button Clicks

```python
import streamlit as st

st.header("Session State Demonstration")

# 1. Initialize the state variable if it doesn't exist
if 'analyse_clicks' not in st.session_state:
    st.session_state['analyse_clicks'] = 0

# 2. Update the state variable on interaction
if st.button("Run Advanced Analysis"):
    st.session_state['analyse_clicks'] += 1

# 3. Access the state variable
st.write(f"You have run the analysis {st.session_state['analyse_clicks']} times.")
```

### Use Case: Advanced Filtering State
Imagine you want a user to apply multiple filters to your Olist data, but you only want the visualisation to update when they click an "Apply" button, not every time they touch a single dropdown.

```python
import streamlit as st

st.subheader("Olist Data Filter")

# Store the filter state
if 'applied_city' not in st.session_state:
    st.session_state['applied_city'] = 'All'

# The selectbox just holds a temporary value
selected_city = st.selectbox("Select a city to analyse:", ["All", "Sao Paulo", "Rio de Janeiro"])

# The state only updates when the button is clicked
if st.button("Apply Filter"):
    st.session_state['applied_city'] = selected_city

st.write(f"Currently viewing data for: **{st.session_state['applied_city']}**")
# (You would then use st.session_state['applied_city'] to filter your cached DataFrame)
```

## 4. Business Impact & Best Practices

As an MBA candidate and Data Analyst, it is crucial to understand the ROI of these technical features:
1. **Compute Cost Reduction:** By caching your MySQL queries and Olist data aggregations, you drastically reduce the load on your servers (or cloud billing).
2. **User Experience (UX):** Stakeholders expect dashboards to be snappy. A 5-second wait for a visualisation to render every time they change a dropdown will lead to poor adoption. Caching solves this.
3. **Complex Workflows:** `st.session_state` allows you to build step-by-step analytical tools (e.g., Step 1: Upload Data -> Step 2: Select Columns -> Step 3: View ML Predictions) rather than overwhelming the user with one massive page.
