# REST API Fundamentals and Data Extraction with Python

## Introduction
In previous modules, we focused on importing static datasets (like flat CSV files) into your VS Code or Jupyter Lab environments. However, in modern business intelligence, data is rarely static. Whether pulling live financial metrics, querying e-commerce shipping status, or fetching real-time healthcare records for an ETL pipeline, you need to extract data directly from the web. 

This is where REST APIs come in. They allow your Python scripts to "talk" to external servers and retrieve live data seamlessly, forming a crucial part of the **Prepare** phase in the data analytics lifecycle.

---

## What is a REST API?
**API** stands for Application Programming Interface. It is a set of rules that allows two software applications to communicate. 
**REST** (Representational State Transfer) is the architectural style most commonly used for web APIs. 

Think of an API like a waiter in a restaurant. You (the client/Python script) look at the menu and give your order to the waiter (the API). The waiter takes your order to the kitchen (the server), and then brings your food (the data) back to you.

---

## Core API Concepts for Data Analysts

### 1. Endpoints
An endpoint is the specific URL where your script sends its request. Just like navigating to a specific folder on your Windows system, different endpoints return different datasets.
* **Base URL:** `https://api.example.com/v1/`
* **Endpoint:** `https://api.example.com/v1/customers` (Returns customer data)

### 2. HTTP Methods
When communicating with an endpoint, you must specify what action you want to perform. As a Data Analyst building pipelines, you will primarily use `GET`, but it is important to know the full CRUD (Create, Read, Update, Delete) mapping:
* **GET (Read):** Retrieves data from the server. (You will use this 95% of the time).
* **POST (Create):** Sends new data to the server.
* **PUT/PATCH (Update):** Modifies existing data.
* **DELETE (Delete):** Removes data.

### 3. HTTP Status Codes
Whenever you make a request, the server returns a 3-digit status code indicating success or failure. You must handle these programmatically in your scripts to prevent your data pipelines from crashing.
* **200 OK:** The request was successful, and the data is returned.
* **400 Bad Request:** Your request was formatted incorrectly.
* **401 Unauthorized:** You are missing authentication (like an API key).
* **403 Forbidden:** You are authenticated but do not have permission to access this specific data.
* **404 Not Found:** The endpoint URL does not exist.
* **500 Internal Server Error:** The server is broken (not your fault).

## Making Your First API Call with Python
To interact with REST APIs, we use the `requests` library in Python. It is the industry standard for making HTTP requests.

### Installation
If you haven't already installed it in your Anaconda environment, you can do so via your terminal:

```bash
pip install requests
```

### Basic GET Request Example
Let's write a simple script to fetch data from a public, free API (JSONPlaceholder) and inspect the response.

```python
import requests

# 1. Define the endpoint URL
url = "https://jsonplaceholder.typicode.com/users"

# 2. Make the GET request
response = requests.get(url)

# 3. Check the status code to ensure success before proceeding
if response.status_code == 200:
    print("Success! Data retrieved.")
    
    # 4. Extract the JSON data
    data = response.json()
    
    # Print the first user in the list to analyse the structure
    print(data[0])
else:
    print(f"Failed to retrieve data. Status Code: {response.status_code}")
```

### Breaking Down the Code:
1.  **`requests.get(url)`**: This initiates the connection to the server.
2.  **`response.status_code`**: We check if we got a `200 OK`. Building conditional logic here is critical for robust data engineering.
3.  **`response.json()`**: APIs almost always return data in JSON (JavaScript Object Notation) format. This method automatically converts the raw JSON string into a Python dictionary or list, making it ready to be loaded into Pandas.
