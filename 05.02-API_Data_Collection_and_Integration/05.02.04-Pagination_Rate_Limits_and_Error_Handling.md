# API Data Collection: Pagination, Rate Limits, and Error Handling

## Introduction
When collecting data from external APIs for business analysis, you will rarely receive the entire dataset in a single response. Servers protect their resources by breaking data into chunks (Pagination) and restricting how frequently you can request data (Rate Limiting). Furthermore, network instability or server issues can cause requests to fail. 

To build robust, production-ready data pipelines, your Python scripts must be able to navigate these constraints automatically without crashing. 

---

## 1. Handling Pagination
APIs limit the number of records returned per request (e.g., 100 rows at a time). To get the next batch, you must request the next "page." There are two primary methods APIs use for pagination: Offset-based and Cursor-based.

### A. Offset-Based Pagination
This method relies on `limit` (how many records to return) and `offset` (how many records to skip). It is very similar to SQL's LIMIT and OFFSET clauses.

``` python
import requests

base_url = "https://api.example.com/data"
limit = 100
offset = 0
all_data = []

while True:
    params = {
        "limit": limit,
        "offset": offset
    }
    
    response = requests.get(base_url, params=params)
    data = response.json()
    
    # Break the loop if no more data is returned
    if not data.get("results"):
        break
        
    all_data.extend(data["results"])
    offset += limit
    
print(f"Total records extracted: {len(all_data)}")
```

### B. Cursor-Based Pagination
Cursor pagination is more efficient and common in modern APIs. Instead of skipping rows mathematically, the API returns a `next_cursor` or `next_page_url` token in the response payload, which you pass into your subsequent request.

``` python
import requests

base_url = "https://api.example.com/data"
all_data = []
next_cursor = None

while True:
    # If a cursor exists, pass it; otherwise, send an empty dictionary
    params = {"cursor": next_cursor} if next_cursor else {}
    
    response = requests.get(base_url, params=params)
    data = response.json()
    
    all_data.extend(data.get("results", []))
    
    # Check if a next cursor exists to continue the loop
    next_cursor = data.get("next_cursor")
    if not next_cursor:
        break
        
print(f"Total records extracted: {len(all_data)}")
```

## 2. Respecting Rate Limits
APIs implement rate limits (e.g., "50 requests per minute") to prevent server overload. If you exceed this limit, the API will cut you off and return an **HTTP 429 (Too Many Requests)** error.

To prevent this, use Python's built-in `time` module to deliberately pause your script between loop iterations.

``` python
import requests
import time

urls_to_fetch = ["https://api.example.com/item/1", "https://api.example.com/item/2", "https://api.example.com/item/3"]
results = []

for url in urls_to_fetch:
    response = requests.get(url)
    
    if response.status_code == 200:
        results.append(response.json())
    
    # Pause script execution for 1.5 seconds before the next request
    time.sleep(1.5) 
```

## 3. Error Handling and Retry Logic
In real-world data extraction, APIs timeout, remote servers crash (HTTP 50X), and network connections drop. A professional script anticipates these failures and attempts to recover gracefully using `try-except` blocks.

### Implementing a Robust Retry Mechanism
Here is an architecture pattern that attempts a request up to 3 times before failing. This ensures that a temporary 2-second network hiccup does not crash a pipeline that has been running for an hour.

``` python
import requests
import time

url = "https://api.example.com/fragile-endpoint"
max_retries = 3
retry_delay = 5 # seconds

for attempt in range(max_retries):
    try:
        # Add a timeout to prevent the script from hanging indefinitely
        response = requests.get(url, timeout=10)
        
        # raise_for_status() triggers an HTTPError if the status code is 4XX or 5XX
        response.raise_for_status() 
        
        data = response.json()
        print("Data extraction successful!")
        break # Exit the retry loop if successful
        
    except requests.exceptions.HTTPError as errh:
        print(f"HTTP Error: {errh}")
        # If it's a 400-level error (e.g., 401 Unauthorized, 404 Not Found), retrying won't help.
        if response.status_code < 500:
            break 
            
    except requests.exceptions.ConnectionError as errc:
        print(f"Error Connecting: {errc}")
    except requests.exceptions.Timeout as errt:
        print(f"Timeout Error: {errt}")
    except requests.exceptions.RequestException as err:
        print(f"Critical API Error: {err}")
        
    print(f"Attempt {attempt + 1} failed. Retrying in {retry_delay} seconds...")
    time.sleep(retry_delay)
else:
    # This 'else' belongs to the 'for' loop. It triggers only if the loop never encounters a 'break'.
    print("All retry attempts exhausted. Pipeline failed.")
```
