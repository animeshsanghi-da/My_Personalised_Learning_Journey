# Applied A/B Testing for Business Strategy

## Introduction
While predictive models can forecast what *might* happen, A/B Testing (or Split Testing) is the gold standard for proving what *actually* works. It bridges the gap between data science and business strategy by providing a mathematical framework to test hypotheses, measure causal impact, and drive ROI.

Whether you are optimising a digital storefront, tweaking a recommendation algorithm, or testing promotional offers for a retail or quick-service restaurant (QSR) environment, mastering A/B testing is essential for making data-driven decisions that replace executive guesswork.

---

## 1. The Anatomy of an A/B Test

An A/B test is a randomized experiment with two variants: **A (The Control)** and **B (The Variant)**. 

### Key Terminology:
* **Control Group:** The segment of users that experiences the current baseline (the status quo).
* **Variant Group:** The segment that experiences the new feature, pricing, or design.
* **Primary Metric (OEC):** Overall Evaluation Criterion. The single most important metric you are trying to move (e.g., Conversion Rate, Average Order Value).
* **Secondary/Guardrail Metrics:** Metrics you monitor to ensure your test doesn't break something else (e.g., ensuring an increase in clicks doesn't lead to a massive drop in profitability).
* **Minimum Detectable Effect (MDE):** The smallest improvement you care about. If a new promo strategy only increases sales by 0.01%, the business cost of implementing it might outweigh the gain.
* **Statistical Power (1 - Beta):** The probability of finding a true effect when one exists (usually set at 80%).
* **Statistical Significance (Alpha):** The probability of finding an effect when one *doesn't* exist (a False Positive, usually set at 5% or 0.05).

---

## 2. The 5-Step A/B Testing Framework

### Step 1: Formulate the Hypothesis
A strong hypothesis defines the exact change and the expected business outcome.
* *Poor Hypothesis:* "Changing the discount type will get more orders."
* *Strong Hypothesis:* "Changing the Zomato promo from 'Flat 20% Off' (Control) to 'Buy One Get One Free' (Variant) for the Momos category will increase the overall order conversion rate by at least 2%."

### Step 2: Calculate Sample Size
Before launching, you must know how many observations you need to achieve statistical significance. Running tests on too few users leads to false conclusions. (This is typically calculated using Python's `statsmodels` library or an online A/B testing calculator).

### Step 3: Randomization and Execution
Users must be randomly assigned to the Control and Variant groups to ensure that external variables (like time of day, weather, or day of the week) impact both groups equally.

### Step 4: Analyse the Results
Once the required sample size is reached, you run statistical tests (like a Z-test for conversion rates or a T-test for continuous metrics like revenue) to determine if the difference is statistically significant.

### Step 5: The Business Decision (Act)
If the p-value < 0.05 (Alpha), you reject the null hypothesis and roll out the winning variant. If not, you retain the control.

## 3. Business Scenario & Python Implementation

Imagine you are managing the digital storefront for a fast-food brand operating out of a major mall in Indore. You want to test two different promotional banners for your evening snack menu. 

* **Control (A):** Standard Menu Layout
* **Variant (B):** High-Contrast 'Combo Offer' Banner

We will use Python, Pandas, and Statsmodels to analyse the results of this simulated experiment.

```python
import pandas as pd
import numpy as np
from statsmodels.stats.proportion import proportions_ztest

# 1. Simulated Experiment Data
# Group A (Control) vs Group B (Variant)
data = {
    'group': ['Control', 'Variant'],
    'total_visitors': [5000, 5000],  # Equal split
    'orders_placed': [410, 480]      # Conversions
}

df = pd.DataFrame(data)

# Calculate Conversion Rates
df['conversion_rate'] = (df['orders_placed'] / df['total_visitors']) * 100
print("--- Conversion Rates ---")
print(df[['group', 'conversion_rate']])

# 2. Statistical Testing (Z-Test for Proportions)
# Extract the successes and the number of trials
successes = np.array(df['orders_placed'])
trials = np.array(df['total_visitors'])

# Perform the Z-test
z_stat, p_value = proportions_ztest(count=successes, nobs=trials, alternative='two-sided')

print("\n--- Statistical Analysis ---")
print(f"Z-Statistic: {z_stat:.4f}")
print(f"P-Value: {p_value:.4f}")

# 3. Business Decision Logic
alpha = 0.05
if p_value < alpha:
    print("\nResult: The difference is statistically significant. The Variant outperformed the Control.")
    print("Action: Roll out the 'Combo Offer' Banner to 100% of the audience.")
else:
    print("\nResult: The difference is NOT statistically significant.")
    print("Action: Retain the Control. Do not implement the new banner.")
```

## 4. Common Pitfalls to Avoid (The "Data Traps")

1. **The Peeking Problem:** Checking the results of your test before reaching the calculated sample size. A test might look significant on Day 2 due to random variance, only to normalize by Day 7. Never stop a test early just because it "looks like it's winning."
2. **Novelty Effect:** Users might interact with a new feature simply because it is new, artificially inflating the variant's performance. Once the novelty wears off, the metric drops. Running the test for a full business cycle (e.g., 2-4 weeks) mitigates this.
3. **Simpson’s Paradox:** A trend that appears in different groups of data disappears or reverses when these groups are combined. Always ensure your randomization is clean and analyse your data both in aggregate and segmented (e.g., Desktop vs. Mobile).
