# 📝 [Python Logging](https://docs.python.org/3/library/logging.html): The Data Analyst's Diagnostic Tool

In data analysis, things don't always go according to plan. Whether it's a missing API response, a malformed JSON file, or a database connection timeout, you need a way to track what happened without staring at the terminal. **Logging** is the professional way to record the "pulse" of your data pipelines.
Logging is a built in module in python which doesn't require any installation.

---

## 🚀 Why Logging Beats `print()`
1.  **Severity Levels:** You can distinguish between a minor "info" message and a "critical" pipeline failure.
2.  **Persistence:** Logs are saved to files for later audit, whereas `print()` statements vanish when the terminal closes.
3.  **Metadata:** Logs automatically include timestamps, line numbers, and the name of the function where the event occurred.

---

## 🛠️ The 5 Severity Levels
|     | Level        | Severity | When to Use It                                                         |
| :-- | :----------- | :------- | :--------------------------------------------------------------------- |
| 1.  | **DEBUG**    | 10       | Detailed diagnostic info (e.g., raw API payloads).                     |
| 2.  | **INFO**     | 20       | Confirmation that things are working (e.g., "Data ingestion started"). |
| 3.  | **WARNING**  | 30       | Something unexpected happened, but the script is still running.        |
| 4.  | **ERROR**    | 40       | A serious problem occurred; a specific task failed.                    |
| 5.  | **CRITICAL** | 50       | The entire program must stop (e.g., Database is down).                 |

## ⚙️ Basic Configuration
The `logging.basicConfig()` method allows you to set up the default behavior of your logger.

```python
import logging

# Configure logging to save to a file with a professional format
logging.basicConfig(
    level=logging.INFO, # setting level to INFO, all levels above INFO are executed, default level is WARNING.
    filename="data_pipeline.log",
    filemode="a", # 'a' for append, 'w' for overwrite
    format="%(asctime)s - %(name)s - %(levelname)s : %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S"
)

logging.info("Pipeline started successfully.")
logging.warning("Memory usage is reaching 80%.")
logging.error("Failed to parse row #452.")
```

## 🏗️ Advanced Logging for Data Projects
For larger projects, creating a **Custom Logger** prevents logs from different modules from getting mixed up.

### 1. Creating a Modular Logger
```python
import logging

# Create a logger for a specific module (e.g., 'data_cleaner')
logger = logging.getLogger("DataCleaner")
logger.setLevel(logging.DEBUG)

# Create a console handler (to see logs in terminal)
console_handler = logging.StreamHandler()
console_handler.setLevel(logging.INFO)
# Create a file handler (to see logs in file)
file_handler = logging.FileHandler("data_pipeline.log")
file_handler.setLevel(logging.DEBUG)

# Create a format and add it to the (console or file) handler
formatter1 = logging.Formatter('%(name)s | %(levelname)s | %(message)s')
formatter2 = logging.Formatter('%(asctime)s - %(name)s - %(levelname)s : %(message)s',datefmt="%Y-%m-%d %H:%M:%S")
console_handler.setFormatter(formatter1)
file_handler.setFormatter(formatter2)

# Add the handler to the logger
logger.addHandler(console_handler)
logger.addHandler(file_handler)

logger.info("Custom logger is ready to process data.")
```

It is best practice to use a utility file to improve readability and adhere to the DRY (Don’t Repeat Yourself) principle. ### 2. Tracking Exceptions (Tracebacks)
When a data script crashes, you want the full error report in your logs. Use `exc_info=True`.

```python
try:
    result = 10 / 0  # Simulating a math error in analysis
except Exception as e:
    logging.error("An error occurred during calculation", exc_info=True)
```

## 💡 Best Practices for Data Analysts
1.  **Don't Log Passwords:** Never log `.env` variables or API keys.
2.  **Log the Data Shape:** Log the number of rows read (e.g., `logger.info(f"Loaded {df.shape[0]} rows")`).
3.  **Rotate Logs:** For long-running scripts, use `RotatingFileHandler` to prevent log files from growing into Gigabytes.
