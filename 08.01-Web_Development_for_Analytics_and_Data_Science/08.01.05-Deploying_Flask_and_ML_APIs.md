# Capstone: Deploying Flask and Machine Learning APIs

## Introduction
Building a machine learning model is only half the battle. To generate real business value as a Data Analyst or Business Intelligence Analyst, stakeholders need a way to interact with your predictive models. 

In this module, we bridge the gap between local environments and production by wrapping a `scikit-learn` predictive model—such as the Linear Regression model used to analyse the Olist E-Commerce dataset—into a Flask API, and deploying it live on modern cloud platforms like Render.

## 1. Serializing the Model (Pickling)
Before creating the API, the trained model must be saved to a file so it doesn't need to be retrained every time the server starts.

``` python
import pandas as pd
from sklearn.linear_model import LinearRegression
import pickle

# Assuming 'X_train' and 'y_train' are derived from your e-commerce dataset
model = LinearRegression()
model.fit(X_train, y_train)

# Save the model to disk
with open('olist_lr_model.pkl', 'wb') as file:
    pickle.dump(model, file)
```

## 2. Building the Flask API
In your VS Code workspace, create an `app.py` file. This script will load the serialized model and expose a web endpoint that accepts new data and returns predictions.

``` python
from flask import Flask, request, jsonify
import pickle
import numpy as np

app = Flask(__name__)

# Load the trained model at startup
with open('olist_lr_model.pkl', 'rb') as file:
    model = pickle.load(file)

@app.route('/predict', methods=['POST'])
def predict():
    # Receive JSON data from the request
    data = request.get_json()
    
    # Extract features (e.g., freight_value, product_weight_g)
    features = [data['freight_value'], data['product_weight_g']]
    final_features = [np.array(features)]
    
    # Make prediction
    prediction = model.predict(final_features)
    
    # Return the result as a JSON response
    return jsonify({'predicted_delivery_days': round(prediction[0], 2)})

if __name__ == "__main__":
    app.run(debug=True)
```

## 3. Preparing for Deployment
Cloud platforms are blank slates. They need specific files to know what dependencies to install and how to run your application.

### requirements.txt
Generate this file so the server installs exactly the packages you used locally:
``` text
Flask==2.3.2
scikit-learn==1.3.0
numpy==1.25.2
gunicorn==21.2.0
```
*(Note: `gunicorn` is the production-grade Python web server that will run your Flask app on the cloud, replacing Flask's built-in development server).*

### Procfile (Optional but Recommended)
If deploying to platforms like Railway, a `Procfile` strictly defines the process type and command:
``` text
web: gunicorn app:app
```

## 4. Deploying to Render
Render connects directly to your version control, making CI/CD (Continuous Integration/Continuous Deployment) seamless.

1. Push your project files (`app.py`, `olist_lr_model.pkl`, `requirements.txt`, and optionally `Procfile`) to a new repository on your GitHub account (e.g., `https://github.com/animeshsanghi-da/Olist-ML-API`).
2. Log in to Render (render.com) and click **New +** -> **Web Service**.
3. Connect your GitHub account and select your newly created repository.
4. Render will auto-detect Python. Ensure the settings match:
   * **Build Command:** `pip install -r requirements.txt`
   * **Start Command:** `gunicorn app:app`
5. Click **Deploy Web Service**.

Once the build and deployment process finishes, Render will provide a live URL (e.g., `https://olist-ml-api.onrender.com`). You can test your deployed API using Postman or a simple Python `requests` script to send POST requests and receive live predictions from your model.
