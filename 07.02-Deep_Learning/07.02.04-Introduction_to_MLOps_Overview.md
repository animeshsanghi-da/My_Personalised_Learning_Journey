# Introduction to MLOps: Bridging the Gap Between Notebooks and Production

## Overview
In the previous modules (specifically `07.02.03`), we explored how to train a machine learning model using Scikit-learn and serialise it using `joblib` or `pickle`. While this is sufficient for local analysis or a standalone predictive API, enterprise environments require a more robust approach to handle continuous data streams and scalable infrastructure.

This is where **MLOps (Machine Learning Operations)** comes in. 

For someone targeting Data Analyst or Business Intelligence roles, you do not need to be an MLOps architect right now—that is typically a senior or specialised Machine Learning Engineer skillset. However, understanding the vocabulary and the lifecycle of a model in production is a highly attractive signal in interviews. It shows you understand what happens to your data and models *after* the initial analysis is complete.

---

## What is MLOps?
MLOps is a set of practices that aims to deploy and maintain machine learning models in production reliably and efficiently. It is the intersection of Machine Learning, DevOps (Software Development Operations), and Data Engineering.

Think of the 6-stage data process (Ask, Prepare, Process, Analyse, Share, Act). MLOps heavily governs the transition from **Analyse** (building the model) to **Act** (deploying the model so it can make automated business decisions reliably every single day).

---

## The Core Pillars of MLOps
While you don't need to build these systems from scratch, you should understand the purpose of the standard tools in the modern MLOps stack.

### 1. Versioning (Code, Data, and Models)
In standard software engineering, you use Git to version your code. But Git cannot handle massive datasets (like a 100,000+ row e-commerce dataset) or large model weight files.
* **The Solution:** Tools like **DVC (Data Version Control)** track changes in your raw datasets and trained models, ensuring that you can reproduce an exact experiment from six months ago.

### 2. Experiment Tracking
When tuning a Linear Regression or an algorithm, you might run dozens of experiments with different parameters. Keeping track of this in an Excel sheet or a notebook becomes inefficient.
* **The Solution:** Tools like **MLflow** or **Weights & Biases (W&B)** log every parameter, metric (like RMSE or R-squared), and model artifact automatically. 

### 3. CI/CD for Machine Learning (Automation)
Continuous Integration and Continuous Deployment (CI/CD) means automating the testing and deployment process. 
* **The Concept:** If you push new Python code or updated training data to your `animeshsanghi-da` GitHub repository, a tool like **GitHub Actions** can automatically trigger a pipeline to retrain your model, test its accuracy, and deploy the new version to a live server without manual intervention.

### 4. Containerisation and Orchestration
Models need to run in consistent environments so they don't break due to missing dependencies (the classic "it works on my machine" problem).
* **The Solution:** **Docker** packages your model, Python version, and libraries into an isolated container. For massive scale, **Kubernetes** or **Kubeflow** manages thousands of these containers.

### 5. Model Monitoring (Drift)
A deployed model is not a finished product; models degrade over time because the real world changes.
* **Data Drift:** The incoming data changes (e.g., customer purchasing habits shift suddenly).
* **Model Drift (Concept Drift):** The fundamental relationship between the features and the target variable changes, meaning your model's predictions become less accurate.
* **The Solution:** MLOps monitoring tools continuously evaluate live model accuracy against actual outcomes and alert you if the model needs retraining.

## What You Actually Need to Know (The Analyst Perspective)
As a Data Analyst or BI professional, you should focus on the following core competencies to interface smoothly with engineering teams:
1. **Know the Terminology:** Be able to clearly explain the difference between data drift and concept drift in a business context.
2. **Keep Your Code Clean:** Write modular, well-documented Python code. Avoid massive, messy Jupyter notebooks for final deliverables. Move reusable functions into `.py` files.
3. **Understand the Hand-off:** Know how to save your Scikit-learn models, document your features thoroughly via a data dictionary, and hand over a clean `requirements.txt` file.
4. **Stay Applied:** Focus your energy on delivering core business value: rigorously cleaning data, conducting deep exploratory data analysis, building strong predictive models, and creating actionable visualisations.
