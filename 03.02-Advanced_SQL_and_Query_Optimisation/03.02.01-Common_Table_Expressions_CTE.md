# Advanced SQL: Common Table Expressions (CTEs)

## Introduction
As a Data Analyst, writing SQL queries that return the correct data is only half the battle; the other half is writing code that is readable, maintainable, and modular. 

A Common Table Expression (CTE) allows you to define a temporary, named result set that you can reference within a `SELECT`, `INSERT`, `UPDATE`, or `DELETE` statement. Introduced via the `WITH` clause, CTEs act as virtual tables created on the fly during query execution. They are the ultimate tool for simplifying complex nested subqueries.

## 1. The Syntax of a CTE
A CTE is defined using the `WITH` keyword, followed by the CTE name, the query that defines it, and finally the main query that uses it.

``` sql
WITH cte_name AS (
    -- Your CTE query goes here
    SELECT column1, column2
    FROM original_table
    WHERE condition
)
-- Main query referencing the CTE
SELECT *
FROM cte_name;
```

## 2. Why use CTEs? (CTEs vs. Subqueries)
Imagine we want to analyse customer purchase behaviour in our Olist E-Commerce dataset. We want to find customers who have spent more than the average customer.

### The "Old Way" (Nested Subquery)
Nested subqueries are evaluated from the inside out. They are hard to read, require mental gymnastics to track, and are incredibly difficult to debug.

``` sql
SELECT customer_id, total_spent
FROM (
    SELECT customer_id, SUM(payment_value) AS total_spent
    FROM order_payments
    GROUP BY customer_id
) AS customer_totals
WHERE total_spent > (
    SELECT AVG(total_spent)
    FROM (
        SELECT customer_id, SUM(payment_value) AS total_spent
        FROM order_payments
        GROUP BY customer_id
    ) AS avg_totals
);
```

### The "Clean Way" (Using a CTE)
CTEs allow us to declare our logic top-down, exactly how our brain processes the sequential steps of data manipulation.

``` sql
WITH CustomerTotals AS (
    SELECT customer_id, SUM(payment_value) AS total_spent
    FROM order_payments
    GROUP BY customer_id
),
AverageSpend AS (
    SELECT AVG(total_spent) AS avg_spent
    FROM CustomerTotals
)

-- Main Query
SELECT ct.customer_id, ct.total_spent
FROM CustomerTotals ct
CROSS JOIN AverageSpend a
WHERE ct.total_spent > a.avg_spent;
```

*Notice how we chained multiple CTEs together using a comma? This modular approach makes debugging incredibly easy. You can simply change the final `SELECT` statement to query one of the intermediate CTEs (e.g., `SELECT * FROM CustomerTotals`) to test your logic at a specific step.*

## 3. Advanced Application: Chaining CTEs for Business Intelligence
In professional analytics, you rarely write a single transformation. CTEs allow you to build sequential data pipelines within a single SQL script. 

**Scenario:** We need to analyse regional sales performance, but only for regions that have a robust network of more than 50 active sellers.

``` sql
WITH ActiveSellers AS (
    -- Step 1: Filter active sellers
    SELECT seller_id, seller_state
    FROM sellers
    WHERE seller_status = 'active'
),
StateSellerCount AS (
    -- Step 2: Count sellers per state
    SELECT seller_state, COUNT(seller_id) as total_sellers
    FROM ActiveSellers
    GROUP BY seller_state
    HAVING COUNT(seller_id) > 50
),
StateRevenue AS (
    -- Step 3: Calculate revenue per state
    SELECT s.seller_state, SUM(oi.price) as total_revenue
    FROM order_items oi
    JOIN sellers s ON oi.seller_id = s.seller_id
    GROUP BY s.seller_state
)

-- Final Output: Combine the logic
SELECT 
    ssc.seller_state, 
    ssc.total_sellers, 
    sr.total_revenue
FROM StateSellerCount ssc
JOIN StateRevenue sr ON ssc.seller_state = sr.seller_state
ORDER BY sr.total_revenue DESC;
```

## 4. A Brief Note on Recursive CTEs
While standard CTEs are used to simplify logic, **Recursive CTEs** are used to query hierarchical data (like organizational reporting charts, category trees, or network graphs). They reference themselves until a stopping condition is met.

``` sql
WITH RECURSIVE NumberSequence AS (
    -- Base Case (Anchor)
    SELECT 1 AS num
    
    UNION ALL
    
    -- Recursive Step
    SELECT num + 1
    FROM NumberSequence
    WHERE num < 10 -- Stopping Condition
)
SELECT * FROM NumberSequence;
```
*(This simple example generates numbers from 1 to 10. In a business context, this is often used to traverse down a management chain from CEO to entry-level employee).*

## 5. Performance Considerations (MySQL Specific)
It is important to note that in MySQL, standard CTEs are largely "syntactic sugar." They do not inherently speed up query execution times compared to a well-written subquery. However, they drastically reduce the time it takes for *humans* to read, analyse, and maintain the code, which is arguably a more critical metric when working collaboratively in a data analytics team.
