# Advanced SQL: Offset Functions for Time Series and Cohort Analysis

## Introduction
When working as a Data Analyst or Business Intelligence professional, standard aggregations like `SUM()` and `AVG()` are often insufficient for answering dynamic business questions. Tracking metrics over time—such as Month-over-Month (MoM) revenue growth, identifying customer churn, or analysing cohort behaviour—requires comparing a row with preceding or succeeding rows. 

This is where **Offset Functions** become invaluable. They allow you to shift data up or down without relying on complex, resource-heavy self-joins.

---

## 1. LAG() and LEAD(): Calculating Period-over-Period Growth

The `LAG()` and `LEAD()` functions are the backbone of time series analysis. They retrieve data from a previous or subsequent row in the same result set, respectively.

### Syntax
``` sql
LAG(column_name, offset, default_value) OVER (
    [PARTITION BY partition_col] 
    ORDER BY order_col
)
```

* **offset:** How many rows to look back/forward (default is 1).
* **default_value:** What to return if the offset goes out of bounds (e.g., returning 0 instead of NULL for the first month).

### Business Use Case: E-Commerce Revenue Growth (MoM)
Imagine working with a large-scale e-commerce database (similar to the Olist dataset). A common requirement is to analyse monthly sales and calculate the percentage growth compared to the previous month.

``` sql
WITH MonthlySales AS (
    SELECT 
        DATE_FORMAT(order_purchase_timestamp, '%Y-%m') AS order_month,
        SUM(payment_value) AS total_revenue
    FROM 
        ecommerce_payments
    GROUP BY 
        DATE_FORMAT(order_purchase_timestamp, '%Y-%m')
)
SELECT 
    order_month,
    total_revenue,
    LAG(total_revenue, 1) OVER (ORDER BY order_month) AS previous_month_revenue,
    -- Calculating Month-over-Month Growth Percentage
    ROUND(
        ((total_revenue - LAG(total_revenue, 1) OVER (ORDER BY order_month)) 
        / LAG(total_revenue, 1) OVER (ORDER BY order_month)) * 100, 2
    ) AS mom_growth_percentage
FROM 
    MonthlySales;
```

**How it works:** The CTE aggregates the raw data into monthly totals. The main query then uses `LAG()` to pull the previous month's revenue into the current row, making the percentage math straightforward. `LEAD()` functions identically but looks forward, which is useful for predictive models or forecasting scenarios.

## 2. FIRST_VALUE() and LAST_VALUE(): Analysing Cohort Behaviour

While `LAG()` and `LEAD()` look at adjacent rows, `FIRST_VALUE()` and `LAST_VALUE()` pinpoint the absolute boundaries of a partition. This is essential for cohort analysis and mapping the customer journey.

### Syntax & The "Frame" Trap
``` sql
FIRST_VALUE(column_name) OVER (
    [PARTITION BY partition_col] 
    ORDER BY order_col
    [ROWS/RANGE frame_clause]
)
```

**⚠️ Critical Warning for LAST_VALUE():** By default, the SQL window frame ends at the *current row* (`RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`). This means `LAST_VALUE()` will often just return the current row's value. To find the true last value in the partition, you must explicitly expand the frame to the end of the partition:
`ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`

### Business Use Case: Customer Journey and Retention
To understand customer retention, a business might want to compare a customer's very first purchase date with their most recent one, and identify their first purchased product category.

``` sql
SELECT 
    customer_id,
    order_date,
    product_category,
    -- Finds the first ever purchase date for this specific customer
    FIRST_VALUE(order_date) OVER (
        PARTITION BY customer_id 
        ORDER BY order_date
    ) AS first_purchase_date,
    
    -- Finds the first category they ever bought
    FIRST_VALUE(product_category) OVER (
        PARTITION BY customer_id 
        ORDER BY order_date
    ) AS acquisition_category,
    
    -- Finds their most recent purchase date (requires the extended frame!)
    LAST_VALUE(order_date) OVER (
        PARTITION BY customer_id 
        ORDER BY order_date 
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS most_recent_purchase_date
FROM 
    customer_orders;
```

**How it works:** By partitioning by `customer_id`, we isolate each user's history. `FIRST_VALUE()` allows us to tag every single order with the customer's "acquisition date" and "acquisition category". This enables analysts to build cohorts (e.g., "How do users who first bought Electronics behave 6 months later compared to those who first bought Apparel?").

## Summary for Data Analysts
1. Use **LAG()** to compare current performance against past performance (MoM, YoY).
2. Use **LEAD()** to calculate time gaps (e.g., days between the current order and the next order).
3. Use **FIRST_VALUE()** to establish a baseline for a customer, product, or time period (Cohort creation).
4. Use **LAST_VALUE()** carefully, always remembering to adjust the window frame to `UNBOUNDED FOLLOWING`. 
5. Always ensure your queries are clean, well-commented, and computationally efficient, especially when dealing with databases containing millions of rows.
