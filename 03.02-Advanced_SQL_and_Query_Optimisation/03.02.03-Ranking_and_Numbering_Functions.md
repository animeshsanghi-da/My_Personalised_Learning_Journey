# Advanced SQL: Ranking and Numbering Functions

## Introduction
When analysing large datasets—such as transactional records in an e-commerce database—you frequently need to rank items, find the "top 5" in a specific category, or identify the latest transaction for a customer. 

In technical interviews for Data Analyst and Business Intelligence roles, standard aggregations are rarely enough. Interviewers will specifically test your understanding of three critical Window Functions: `ROW_NUMBER()`, `RANK()`, and `DENSE_RANK()`. 

Understanding the precise differences in how these functions handle **ties** (identical values) is essential for accurate data reporting.

---

## 1. The "Big Three" Ranking Functions

All three functions assign a sequential integer to rows within a partition of a result set. The difference lies entirely in how they behave when two rows have the exact same value in the `ORDER BY` clause.

* **`ROW_NUMBER()`**: Assigns a **strictly unique** sequential integer to each row. Even if two rows have the exact same value, they will get different row numbers (usually determined randomly or by physical order if no secondary tie-breaker is provided).
* **`RANK()`**: Assigns the **same rank to identical values**, but leaves a "gap" in the subsequent ranking. For example, if two items tie for 2nd place, the next item will be ranked 4th (1, 2, 2, 4).
* **`DENSE_RANK()`**: Assigns the **same rank to identical values**, but does **not leave gaps**. If two items tie for 2nd place, the next item will be ranked 3rd (1, 2, 2, 3).

---

## 2. Side-by-Side Comparison

To illustrate this perfectly, let us look at a practical scenario. Imagine we are analysing a subset of an e-commerce dataset (similar to the Olist data) and we want to rank sellers based on their total sales.

### The Query

``` sql
SELECT 
    seller_id,
    total_sales,
    ROW_NUMBER() OVER(ORDER BY total_sales DESC) AS row_num,
    RANK() OVER(ORDER BY total_sales DESC) AS rank_val,
    DENSE_RANK() OVER(ORDER BY total_sales DESC) AS dense_rank_val
FROM 
    seller_performance;
```

### The Result Set

| seller_id | total_sales | row_num | rank_val | dense_rank_val |
|-----------|-------------|---------|----------|----------------|
| S-101     | 50,000      | 1       | 1        | 1              |
| S-102     | 45,000      | 2       | 2        | 2              |
| S-103     | 45,000      | 3       | 2        | 2              |
| S-104     | 40,000      | 4       | 4        | 3              |
| S-105     | 30,000      | 5       | 5        | 4              |

**Analysis of the Output:**
* Notice `S-102` and `S-103` both have `45,000` in sales.
* `row_num` blindly assigns 2 and 3.
* `rank_val` assigns 2 to both, but the next seller (`S-104`) gets rank **4**. (Rank 3 is skipped).
* `dense_rank_val` assigns 2 to both, and the next seller (`S-104`) gets rank **3**. No gaps!

## 3. Real-World Business Use Case: Finding the Top 'N' per Category

A classic Business Intelligence request: *"Give me the top 3 best-selling products in every single category."*

You cannot solve this with a simple `ORDER BY ... LIMIT 3`, because that only gives you the top 3 products across the *entire* table, not *per category*. 

To solve this, we combine a **Common Table Expression (CTE)** with `DENSE_RANK()` and `PARTITION BY`. We use `DENSE_RANK()` because if two products tie for 1st place, we still want to ensure we capture the 2nd and 3rd place products properly without skipping numbers.

### The Solution

``` sql
WITH RankedProducts AS (
    SELECT 
        product_id,
        category,
        sales_amount,
        DENSE_RANK() OVER(
            PARTITION BY category 
            ORDER BY sales_amount DESC
        ) as sales_rank
    FROM 
        product_sales
)
SELECT 
    product_id,
    category,
    sales_amount,
    sales_rank
FROM 
    RankedProducts
WHERE 
    sales_rank <= 3;
```

### Why This Works:
1. **`PARTITION BY category`**: This resets the ranking counter back to 1 every time the SQL engine encounters a new category.
2. **`ORDER BY sales_amount DESC`**: This determines the actual ranking order (highest sales gets rank 1).
3. **The CTE (`WITH RankedProducts AS ...`)**: Window functions cannot be used directly in a `WHERE` clause. By placing the window function inside a CTE, we can filter on the `sales_rank` alias in the outer query, making query optimisation much easier for the database engine.

---

## Summary
* Use **`ROW_NUMBER()`** when you need strict pagination, deduplication (finding the first instance of a record), or to guarantee exactly one row per rank.
* Use **`RANK()`** when ties matter and you want the rank number to reflect the absolute total number of items ahead of it.
* Use **`DENSE_RANK()`** (most common in analytics) when categorising items into distinct tiers without gaps, such as finding the "Top 3 highest earners."
