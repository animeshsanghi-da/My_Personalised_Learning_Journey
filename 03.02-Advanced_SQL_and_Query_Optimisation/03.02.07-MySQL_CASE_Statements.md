# Advanced SQL: Conditional Logic with CASE Statements

## Overview
During the **Process** and **Analyze** stages of the 6-stage data analysis framework, you often encounter raw data that needs to be categorized, transformed, or flagged before it can be effectively visualized and shared. In MySQL, the `CASE` statement acts as the SQL equivalent of an `IF-THEN-ELSE` function. It allows you to embed conditional logic directly into your queries to create new dimensions and derived metrics without permanently altering the underlying tables.

---

## 1. The Anatomy of a CASE Statement
A `CASE` statement evaluates conditions sequentially. Once a condition is met, it returns the corresponding result and stops evaluating. If no conditions are met, it returns the value in the `ELSE` clause.

### Standard Syntax
```sql
SELECT 
    column_name,
    CASE 
        WHEN condition_1 THEN 'Result 1'
        WHEN condition_2 THEN 'Result 2'
        ELSE 'Fallback Result'
    END AS new_derived_column
FROM table_name;
```

*Note: The `ELSE` clause is optional. If omitted and no conditions are met, the statement will return `NULL`.*

---

## 2. Practical Business Application: Data Categorization
When evaluating e-commerce performance—such as reviewing seller delivery times or customer spend in the Olist dataset—we frequently need to group continuous numerical data into discrete, readable buckets. 

**Scenario:** We want to categorize individual order payments to understand purchasing behavior.

```sql
SELECT 
    order_id,
    payment_value,
    CASE 
        WHEN payment_value < 50 THEN 'Low Value'
        WHEN payment_value BETWEEN 50 AND 200 THEN 'Medium Value'
        WHEN payment_value > 200 THEN 'High Value'
        ELSE 'Unknown'
    END AS order_category
FROM order_payments;
```

---

## 3. Simple CASE vs. Searched CASE

### Searched CASE (Most Common)
This is the format used above, where each `WHEN` clause evaluates a full boolean expression. It is highly flexible because you can check multiple different columns or use complex operators (`>`, `<`, `LIKE`, etc.).

### Simple CASE
If you are only comparing a single column against exact values, you can use the Simple CASE syntax. It is cleaner and easier to read.

```sql
SELECT 
    customer_id,
    customer_state,
    CASE customer_state
        WHEN 'SP' THEN 'São Paulo'
        WHEN 'RJ' THEN 'Rio de Janeiro'
        WHEN 'MG' THEN 'Minas Gerais'
        ELSE 'Other Region'
    END AS state_full_name
FROM customers;
```

## 4. Advanced Analytics: Pivoting Data with CASE
One of the most powerful applications of the `CASE` statement for an analyst is using it inside an aggregate function (like `SUM` or `COUNT`). This allows you to pivot rows into columns, which is incredibly helpful when compiling insights for MBA coursework or building structured summary tables for dashboards.

**Scenario:** We want to count how many orders fall into each payment type category, all on a single row.

```sql
SELECT 
    COUNT(CASE WHEN payment_type = 'credit_card' THEN 1 END) AS credit_card_orders,
    COUNT(CASE WHEN payment_type = 'boleto' THEN 1 END) AS boleto_orders,
    COUNT(CASE WHEN payment_type = 'voucher' THEN 1 END) AS voucher_orders
FROM order_payments;
```

*How it works:* The `CASE` statement generates a `1` only when the condition is true. The `COUNT()` function then counts those non-null values, effectively pivoting the categorical rows into distinct, summarized columns.

---

## Summary Best Practices
1. **Order Matters:** `CASE` statements evaluate sequentially. Always put your most specific conditions at the top, and your broadest catch-all conditions at the bottom.
2. **Data Types:** Ensure that all `THEN` results return the exact same data type. You cannot mix strings and integers in the output of a single `CASE` expression.
3. **Always use ELSE:** Even if you think you have covered all possible scenarios, an unexpected `NULL` can break downstream calculations. Providing a fallback `ELSE` value maintains data integrity.
