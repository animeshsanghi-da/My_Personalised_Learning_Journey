# Applied Migration: Olist E-Commerce Dataset to Google BigQuery

## 1. The Business Case for Cloud Migration
Handling the Brazilian Olist E-Commerce dataset locally is an excellent way to practice the 6-stage data process (Ask, Prepare, Process, Analyse, Share, Act) and run predictive models like Linear Regression. However, executing complex analytical queries across 100,000+ rows on a local machine can lead to performance bottlenecks. 

Migrating this data to Google BigQuery shifts the computational load from local hardware to Google's distributed infrastructure. This enables faster query execution, easier integration with live BI dashboards, and enterprise-grade portfolio demonstration.

---

## 2. Pushing Local Data to BigQuery via Python

Instead of manually uploading CSV files through the Google Cloud Console, we will automate the ingestion process using Python and Pandas inside VS Code or Jupyter Lab. 

Ensure you have your Google Cloud Service Account JSON key ready and the `google-cloud-bigquery` library installed.

```python
import os
import pandas as pd
from google.cloud import bigquery
from google.oauth2 import service_account

# 1. Authenticate and Initialise the BigQuery Client
credentials_path = 'path/to/your/service_account_key.json'
credentials = service_account.Credentials.from_service_account_file(credentials_path)
client = bigquery.Client(credentials=credentials, project=credentials.project_id)

# 2. Define the Target Table
project_id = client.project
dataset_id = 'olist_ecommerce_data'
table_id = 'orders_master'
table_ref = f"{project_id}.{dataset_id}.{table_id}"

# 3. Load the Local Dataset using Pandas
# Assuming the data has already been cleaned in previous stages
file_path = '../data/olist_orders_dataset.csv'
df = pd.read_csv(file_path)

# 4. Configure the Load Job
job_config = bigquery.LoadJobConfig(
    write_disposition=bigquery.WriteDisposition.WRITE_TRUNCATE, # Overwrites existing table
    autodetect=True # Automatically infers data types
)

# 5. Execute the Upload
print(f"Uploading {len(df)} rows to {table_ref}...")
job = client.load_table_from_dataframe(df, table_ref, job_config=job_config)
job.result() # Waits for the job to complete

print("Migration successful! Data is now live in BigQuery.")
```

## 3. Executing Advanced Analytics in the Cloud

Now that the 100,000+ rows are stored in BigQuery, we can execute advanced SQL queries in milliseconds. 

The following query utilises a **Common Table Expression (CTE)** and **Window Functions** to analyse seller performance. It calculates total revenue per seller and ranks them within their respective product categories.

```sql
WITH SellerRevenue AS (
    -- CTE: Calculate total revenue and order count per seller, joined with product categories
    SELECT 
        i.seller_id,
        p.product_category_name,
        COUNT(DISTINCT i.order_id) AS total_orders,
        SUM(i.price) AS total_revenue
    FROM 
        `olist_ecommerce_data.order_items` i
    JOIN 
        `olist_ecommerce_data.products` p ON i.product_id = p.product_id
    GROUP BY 
        i.seller_id, 
        p.product_category_name
)

-- Main Query: Apply Window Functions to rank sellers within each category
SELECT 
    seller_id,
    product_category_name,
    total_orders,
    ROUND(total_revenue, 2) AS total_revenue,
    DENSE_RANK() OVER(
        PARTITION BY product_category_name 
        ORDER BY total_revenue DESC
    ) AS category_revenue_rank,
    SUM(total_revenue) OVER(
        PARTITION BY product_category_name
    ) AS total_category_revenue
FROM 
    SellerRevenue
WHERE 
    total_orders > 10 -- Filter out one-off sellers to ensure statistical relevance
ORDER BY 
    product_category_name, 
    category_revenue_rank;
```

### Query Breakdown:
* **`WITH SellerRevenue AS`**: The CTE isolates the foundational aggregations, keeping the main query clean and readable.
* **`DENSE_RANK() OVER(...)`**: Ranks sellers sequentially without skipping numbers if there is a tie. We partition the ranking by the product category, essentially creating a "Top Sellers per Category" leaderboard.
* **`SUM() OVER(...)`**: Calculates the total revenue for the entire category on every row, allowing us to easily calculate the percentage of category revenue a single seller owns in a subsequent BI tool.
