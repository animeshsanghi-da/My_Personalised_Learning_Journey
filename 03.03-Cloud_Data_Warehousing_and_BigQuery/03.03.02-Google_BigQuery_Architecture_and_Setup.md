# Google BigQuery: Architecture, Hierarchy, and Sandbox Setup

## Introduction
As a Data Analyst handling business-scale data, you will quickly outgrow local MySQL environments. Google BigQuery is a fully managed, serverless, enterprise data warehouse that executes SQL queries over terabytes of data in seconds. 

For an MBA candidate and data professional, understanding *how* to navigate this environment is just as important as writing the SQL itself. This module covers how to set up your free analytics environment, navigate the Google Cloud Console, and structure your data logically—preparing you to migrate massive datasets like your 100,000+ row Olist E-Commerce project.

## 1. The BigQuery Sandbox (Zero-Cost Analytics)
Enterprise cloud tools usually require billing accounts, but Google provides the **BigQuery Sandbox**. This allows you to explore BigQuery's capabilities, run queries, and build your portfolio absolutely free, without linking a credit card.

### Sandbox Limits (Perfect for Portfolios):
* **Storage:** 10 GB of active storage per month.
* **Compute/Querying:** 1 TB of query data processed per month.
* *Note:* Tables in the sandbox have a default 60-day expiration, which can be updated later if you upgrade, but is more than enough time for project building and analysis.

### How to Activate:
1. Go to the [Google Cloud Console](https://console.cloud.google.com/).
2. Sign in with your professional email (`animeshsanghi.da@gmail.com`).
3. Accept the Terms of Service.
4. Navigate to **BigQuery** via the search bar or the left-hand hamburger menu. You will automatically be placed in the Sandbox environment.

## 2. Navigating the Google Cloud Console
The Google Cloud Platform (GCP) can look overwhelming because it houses hundreds of services. As a Data Analyst, you only need to focus on a few key areas within the BigQuery UI (The SQL Workspace).

* **Explorer Pane (Left Sidebar):** This is your database tree. It displays your Projects, Datasets, and Tables.
* **SQL Workspace (Main Canvas):** The query editor where you will write, format, and execute your Standard SQL queries.
* **Query Results & Execution Details (Bottom Pane):** Displays your tabular results, JSON formats, and the Execution Details (which shows how long the query took and how many bytes were processed—critical for cost optimisation).
* **Personal History / Saved Queries:** BigQuery automatically logs your past queries, making it easy to recover an analysis you ran days ago.

## 3. The BigQuery Data Hierarchy 
Unlike local MySQL where you simply create a database and add tables, Google Cloud uses a strict three-tier hierarchy to manage billing, permissions, and location.

### Level 1: Project (The Container)
The Project is the highest level. It holds all your cloud resources (BigQuery, Cloud Storage, APIs). 
* **Analyst Mindset:** Think of the Project as the specific "Company" or "Client" you are working for. 
* *Example Naming:* `animesh-portfolio-2026` or `olist-analytics-prod`.

### Level 2: Dataset (The Database)
A Dataset is contained within a Project. It is equivalent to a "Database" in MySQL. Datasets are used to organize tables and control access (e.g., giving the Marketing team access to one dataset, and the HR team access to another).
* **Crucial Step:** When creating a dataset, you must choose a **Data Location** (e.g., `US-multi-region`, `asia-south1`). Data *cannot* be easily moved between regions once set.
* *Example Naming:* `ecommerce_sales_data` or `healthcare_etl_raw`.

### Level 3: Table / View (The Data)
Tables exist within Datasets. This is where your actual rows and columns live. BigQuery supports standard Tables, Partitioned Tables (optimized for cost), and Views (saved logical queries).
* *Example Naming:* `olist_orders`, `olist_customers`.

**The Full SQL Reference Path:**
When querying in BigQuery, you must reference the exact path using backticks:
``` sql
SELECT * FROM `project_name.dataset_name.table_name`
LIMIT 100;
```

## 4. Step-by-Step: Setting Up Your First Workspace
Let's prepare the architecture for your portfolio projects.

### Step 1: Create a Project
1. In the top navigation bar of the Cloud Console, click the **Project Dropdown**.
2. Click **New Project**.
3. Name it `animesh-data-portfolio` (Project IDs are globally unique, so GCP might append numbers to the end).
4. Click **Create** and wait a few moments for the resources to provision.

### Step 2: Create a Dataset
1. In the BigQuery **Explorer pane**, click on your new Project ID.
2. Click the three vertical dots (Actions) next to the Project ID and select **Create dataset**.
3. **Dataset ID:** `olist_ecommerce_analysis`.
4. **Data location:** Select `US (multiple regions)` (often the cheapest and most compatible for public datasets).
5. Leave default expiration settings and click **Create Dataset**.

### Step 3: Verifying the Architecture
You should now see a dropdown arrow next to your Project ID. Clicking it will reveal your `olist_ecommerce_analysis` dataset. It is currently empty, but perfectly structured to ingest your 100,000+ row CSV files, which we will cover in the upcoming modules.

## 5. A Note on IAM (Identity and Access Management)
While you are currently a team of one, enterprise environments require you to understand IAM. IAM is how you grant permissions. 

When you connect Python (Jupyter Lab/VS Code) or Power BI to BigQuery later in this module, you will not log in with a standard username and password. Instead, you will create a **Service Account** (a robot user) in IAM and grant it the `BigQuery Data Viewer` and `BigQuery Job User` roles.
