# Remote Access, Permissions, and Automation: The Cloud Analyst

## Introduction
As a Data Analyst, your local machine (using environments like Jupyter or VS Code) is perfect for development and exploratory data analysis. However, when you build production-grade ETL pipelines or automated reporting scripts (like your phase-based healthcare ETL), they need to run continuously and reliably, independent of your laptop. This is where cloud Virtual Machines (VMs) like AWS EC2 or Google Cloud Compute Engine come in. 

This capstone file bridges the gap between local development and cloud deployment. You will learn how to securely access remote servers, transfer your datasets, set the right execution permissions, and automate your Python scripts using `cron`.

---

## 1. Secure Remote Access (`ssh`)
Secure Shell (SSH) is the standard protocol for securely logging into remote Linux servers. Instead of passwords, modern cloud platforms use cryptographic key pairs (e.g., a `.pem` file) for identity verification.

### The Command:
```bash
ssh -i /path/to/your-key.pem username@remote_ip_address
```

### Key Concepts:
* **`-i` flag:** Specifies the identity file (your private key).
* **`username`:** The default user of the cloud instance (e.g., `ubuntu` for AWS Ubuntu VMs, `ec2-user` for Amazon Linux).
* **Best Practice:** Never share your `.pem` files or commit them to your GitHub repositories. 

---

## 2. Secure File Transfer (`scp`)
Once connected to the cloud, you need to move your Python scripts (`.py`), requirements files, and datasets (like `.csv` files) from your local machine to the remote server. `scp` (Secure Copy Protocol) uses SSH under the hood to transfer files safely across networks.

### Pushing to the Cloud (Local to Remote):
```bash
# Sending a Python script to the remote server's home directory
scp -i /path/to/your-key.pem my_etl_script.py ubuntu@remote_ip_address:~/
```

### Pulling from the Cloud (Remote to Local):
```bash
# Downloading a generated report from the server to your current local directory (.)
scp -i /path/to/your-key.pem ubuntu@remote_ip_address:~/monthly_report.csv .
```

---

## 3. Managing File Permissions (`chmod`)
Linux is a multi-user operating system with strict security. When you upload a Python script, it might only have "read" and "write" permissions, but not "execute" permissions. You must explicitly tell the OS that a file is safe to run.

### The Command:
```bash
# Make a script executable for the owner
chmod +x my_etl_script.py
```

### Understanding Permissions (The 777 System):
Permissions are grouped in threes: **Owner**, **Group**, and **Others**.
* **Read (r)** = 4
* **Write (w)** = 2
* **Execute (x)** = 1

*Example:* running `chmod 755 script.py` gives the owner full control (4+2+1=7), while everyone else can only read and execute (4+1=5).

## 4. Automation with `cron`
`cron` is a time-based job scheduler in Linux. It allows you to run scripts automatically at specified intervals (e.g., every day at midnight, every Monday at 9 AM). This is the backbone of automated Data Engineering and BI reporting.

### Accessing the Cron Table:
```bash
crontab -e
```

### The Cron Syntax (`* * * * *`):
A cron expression consists of five fields followed by the command to execute:
1. Minute (0-59)
2. Hour (0-23)
3. Day of the Month (1-31)
4. Month (1-12)
5. Day of the Week (0-7, where 0 and 7 are Sunday)

### Analytical Use Cases:
```bash
# Run the sales data pipeline every day at 2:00 AM
0 2 * * * /usr/bin/python3 /home/ubuntu/scripts/sales_pipeline.py

# Generate the weekly business intelligence report every Monday at 8:30 AM
30 8 * * 1 /usr/bin/python3 /home/ubuntu/scripts/weekly_report.py >> /home/ubuntu/logs/cron.log 2>&1
```

*Pro-Tip for Analysts:* Always use absolute paths (e.g., `/usr/bin/python3` instead of just `python3`) inside cron jobs. Cron runs in a restricted background environment and might not know where your Python installation lives. Adding `>> cron.log 2>&1` ensures all print statements and errors are saved to a log file for debugging.

## 4. Building Python CLI Utilities for Data Pipelines (`argparse`)

As a Data Analyst, you will frequently write Python scripts that need to be executed automatically via bash scripts, Airflow, or `cron` jobs. Instead of hardcoding file paths, database thresholds, or row limits inside your code, you can build **Command Line Interface (CLI) utilities** using Python's built-in `argparse` module.

This allows your scripts to accept dynamic flags and parameters directly from the terminal.

### A. Core Concepts of `argparse`

`argparse` automatically handles command-line arguments, converts data types, generates help messages (`--help`), and throws clean errors when required inputs are missing.

* **Positional Arguments:** Mandatory inputs that must be provided in order (e.g., input dataset path).
* **Optional Arguments (Flags):** Optional settings prefixed with `-` or `--` (e.g., `--limit`, `--output`, `--verbose`).

### B. Basic CLI Script Structure

``` python
import argparse

# 1. Initialize the parser
parser = argparse.ArgumentParser(
    description="A simple command-line file reader for Data Analysts."
)

# 2. Add Positional Argument (Mandatory)
parser.add_argument("filename", help="Path to the dataset or text file to process.")

# 3. Add Optional Arguments (Flags)
parser.add_argument(
    "-n", "--number", 
    type=int, 
    default=1, 
    help="Number of times to repeat the output (default: 1)."
)

# 4. Parse arguments passed from the terminal
args = parser.parse_args()

# 5. Business Logic Execution
try:
    with open(args.filename, "r") as file:
        content = file.read()
        for i in range(args.number):
            print(f"--- Execution Pass {i + 1} ---")
            print(content.strip())
except FileNotFoundError:
    print(f"Error: The file '{args.filename}' was not found.")
```

#### How to run this from the terminal:
``` bash
# Basic run with default parameters
python my_script.py sales_summary.txt

# Run with optional flag to repeat 3 times
python my_script.py sales_summary.txt -n 3

# View automatically generated documentation
python my_script.py --help
```

### C. Advanced Analyst Example: Automated Batch Data Processor

In production pipelines, analysts use CLI utilities to clean and filter datasets dynamically without editing the script source code.

``` python
import argparse
import pandas as pd

def process_pipeline():
    # Setup Argument Parser
    parser = argparse.ArgumentParser(
        description="Automated Data Cleaning and Batch Processing Utility."
    )
    
    # Arguments definition
    parser.add_argument("input_file", help="Path to the raw CSV dataset.")
    parser.add_argument("-o", "--output", default="cleaned_output.csv", help="Destination path for cleaned CSV.")
    parser.add_argument("-r", "--rows", type=int, help="Limit the number of rows to process.")
    parser.add_argument("-v", "--verbose", action="store_true", help="Print detailed execution logs.")

    args = parser.parse_args()

    # Logging execution details if --verbose flag is used
    if args.verbose:
        print(f"[INFO] Loading raw data from: {args.input_file}")

    try:
        # Load dataset with optional row limit
        df = pd.read_csv(args.input_file, nrows=args.rows)
        
        if args.verbose:
            print(f"[INFO] Successfully loaded {len(df)} rows. Starting data cleaning...")

        # Data Cleaning Pipeline: Remove duplicates & drop missing values
        initial_count = len(df)
        df_clean = df.drop_duplicates().dropna()
        
        if args.verbose:
            print(f"[INFO] Cleaned dataset size: {len(df_clean)} rows (Dropped {initial_count - len(df_clean)} rows).")

        # Export processed file
        df_clean.to_csv(args.output, index=False)
        print(f"[SUCCESS] Processed dataset saved to: {args.output}")

    except FileNotFoundError:
        print(f"[ERROR] Could not locate raw dataset: '{args.input_file}'")
    except Exception as e:
        print(f"[ERROR] Pipeline failed: {str(e)}")

if __name__ == "__main__":
    process_pipeline()
```

#### Terminal Execution Examples for Production:
``` bash
# 1. Quick test run on first 50 rows with verbose execution logging
python data_processor.py raw_orders.csv -r 50 -v

# 2. Production batch run outputting to a specific destination
python data_processor.py raw_orders.csv --output /data/processed/clean_orders_q3.csv --verbose
```

## 5. The Capstone Workflow: End-to-End Execution
Imagine you have just finished testing a healthcare ETL script locally in VS Code. Here is the exact terminal workflow to productionize it on a cloud server:

```bash
# 1. Upload the script and raw dataset to the cloud VM
scp -i my-key.pem healthcare_etl.py raw_data.csv ubuntu@192.168.1.100:~/project/

# 2. SSH into the cloud VM
ssh -i my-key.pem ubuntu@192.168.1.100

# 3. Navigate to the folder and make the script executable
cd project/
chmod +x healthcare_etl.py

# 4. Open the cron editor
crontab -e

# 5. Add the scheduled job (e.g., run every 12 hours at minute 0)
0 */12 * * * /usr/bin/python3 /home/ubuntu/project/healthcare_etl.py >> /home/ubuntu/project/etl.log 2>&1
```
