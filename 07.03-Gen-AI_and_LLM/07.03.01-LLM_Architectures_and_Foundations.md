# LLM Architectures and Foundations

## Overview
Large Language Models (LLMs) represent a foundational shift in how textual data is processed, understood, and generated. Moving beyond static word embeddings and sequential architectures (like RNNs or LSTMs), modern LLMs utilize parallelized deep learning architectures capable of capturing long-range contextual relationships within textual datasets. This module documents the core mathematical, algorithmic, and programmatic building blocks underpinning Generative AI systems.

---

## 1. The Paradigm Shift: Evolution to Transformers
Traditional sequential architectures processed text token-by-token, creating severe bottlenecks and computational constraints during training on massive corpora. The introduction of the Transformer architecture removed these hurdles through native parallelization.



### Core Architectural Variations
* **Encoder-Only (e.g., BERT):** Utilizes bidirectional attention to look at both left and right context. Ideal for predictive classification, named entity recognition (NER), and embedding generation.
* **Decoder-Only (e.g., GPT, Llama, Mistral):** Utilizes causal (masked) attention to ensure a token can only look at preceding tokens. Designed specifically for autoregressive next-token prediction and generative tasks.
* **Encoder-Decoder (e.g., T5, BART):** Maps an input sequence to a latent space and decodes it into a target sequence. Dominant in sequence-to-sequence tasks such as translation, text summarization, and structural data conversion.

---

## 2. The Core Mechanism: Self-Attention
The primary engine driving the capacity of a transformer model is the **Self-Attention** layer. It mathematically calculates the contextual relevance of every word in a sequence relative to every other word.

### Mathematical Formulation
Given an input matrix of embeddings, the model projects it into three distinct matrices using learned weights: Queries ($Q$), Keys ($K$), and Values ($V$).

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

Where:
* $Q \times K^T$ computes raw affinity scores between all tokens.
* $\sqrt{d_k}$ is a scaling factor based on the key dimensionality, preventing gradient vanishing issues during the softmax stage.
* $\text{softmax}$ normalizes the raw affinity scores into a clean probability distribution.
* Multiplying by $V$ scales the value vectors based on attention weights, yielding a context-aware dense vector representation.

### NumPy Representation of Scaled Dot-Product Attention
The following program builds a functional scaled dot-product attention calculation from scratch to demonstrate the mathematical operations explicitly:

```python
import numpy as np

def scaled_dot_product_attention(q, k, v):
    """
    Computes Scaled Dot-Product Attention from scratch.
    """
    # Step 1: Calculate dot product of Q and K transposed
    matmul_qk = np.dot(q, k.T)
    matmul_qk = q @ k.T    # Similar
    
    # Step 2: Scale the scores by the square root of dimensionality of keys
    d_k = q.shape[-1]
    scaled_attention_scores = matmul_qk / np.sqrt(d_k)
    
    # Step 3: Apply softmax to get normalized attention weights
    exp_scores = np.exp(scaled_attention_scores - np.max(scaled_attention_scores, axis=-1, keepdims=True))
    attention_weights = exp_scores / np.sum(exp_scores, axis=-1, keepdims=True)
    
    # Step 4: Multiply weights by Value matrix
    output = np.dot(attention_weights, v)
    
    return output, attention_weights

# Simulation: 3 tokens, vector dimension of 4
np.random.seed(42)
Q = np.random.randn(3, 4)
K = np.random.randn(3, 4)
V = np.random.randn(3, 4)

context_vectors, weights = scaled_dot_product_attention(Q, K, V)
print("Contextualized Output Shape:", context_vectors.shape)
print("Attention Weights Matrix:\n", weights)
```

## 3. Tokenization & Token Pipelines
Before textual strings enter an abstraction matrix, they must undergo tokenization—the process of parsing continuous text strings into discrete atomic sub-word integer entries.



### Primary Frameworks
* **Byte-Pair Encoding (BPE):** Iteratively merges the most frequent pairs of bytes or characters (used by GPT models).
* **WordPiece:** Selects subword segments based on maximizing the likelihood of training data combinations (used by BERT).

### Programmatic Sub-Word Parsing Pipeline
Using Hugging Face's `transformers` library, this code instantiates a production tokenizer to map structural strings into machine-readable tensors.

```python
from transformers import AutoTokenizer

# Initialize a standard production-grade tokenizer
tokenizer = AutoTokenizer.from_pretrained("snowflake/arctic-embed-m-long")

raw_analytical_text = "Exploratory Data Analysis optimizes predictive feature generation."

# Tokenize string into textual subwords
tokens = tokenizer.tokenize(raw_analytical_text)
print("Subword Tokens:", tokens)

# Encode subwords directly into unique integer vocabulary IDs
input_ids = tokenizer.encode(raw_analytical_text)
print("Vocabulary Mapped IDs:", input_ids)

# Convert IDs back to structural strings to audit performance
decoded_text = tokenizer.decode(input_ids)
print("Decoded Reconstructed Sequence:", decoded_text)
```

## 4. Prompt Engineering & Programmatic Control
Interacting with pre-trained or fine-tuned LLM parameters within production pipelines requires structured prompt design patterns. Modern interfaces utilize explicit role delineation (System, User, Assistant) to ensure deterministic outputs.

### Production Execution Framework
The following template structures API-driven token generation loops using environment variables and custom configurations:

```python
import os
from openai import OpenAI
from dotenv import load_dotenv

# Securely bind environment configurations
load_dotenv()

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

def execute_structured_extraction(target_payload: str) -> str:
    """
    Uses structured zero-shot role prompting to convert raw text into 
    predictive JSON data architecture blocks.
    """
    system_instruction = (
        "You are an isolated data engineering parser module. Your sole purpose "
        "is to extract key entities and transform them into flat JSON configurations. "
        "Do not speak conversational text. Return only structural code entries."
    )
    
    user_prompt = f"Parse the following application transaction logs: {target_payload}"
    
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": system_instruction},
            {"role": "user", "content": user_prompt}
        ],
        temperature=0.0,  # Zero out entropy to ensure high structural determinism
        max_tokens=250
    )
    
    return response.choices[0].message.content

log_data = "CRITICAL 2026-05-12 DB_CONN_FAIL User ID 88201 validation timeout after 4500ms."
parsed_output = execute_structured_extraction(log_data)
print(parsed_output)
```
