# Scheduling Scripts: From Local `schedule` to Enterprise `cron`

## Introduction
Writing an automation script is only half the battle. The true value of automation in business intelligence is unlocked when scripts run autonomously, pulling data, transforming it, and sending reports without any manual intervention. 

In this module, we will explore how to schedule Python scripts. We begin with the Python-native `schedule` library for local execution and testing, and then transition to OS-level job schedulers like `cron` (for Linux/Unix enterprise servers) and Windows Task Scheduler, ensuring scripts run consistently in the background.

---

## 1. Local Scheduling with the `schedule` Library

The `schedule` library is a lightweight, intuitive Python package that lets you run Python functions (or any other callable) periodically at pre-determined intervals using a simple, human-readable syntax.

### Why Use `schedule`?
* **No OS dependencies:** It runs purely in Python, making it platform-independent (works exactly the same in VS Code on Windows as it does on a Mac or Linux).
* **Highly readable:** The syntax reads like plain English.
* **Great for active sessions:** Ideal for scripts that need to run continuously while you are actively working or monitoring an application.

### Installation
```bash
pip install schedule
```

### Implementation Example
Let's look at a script that automates a daily ETL task, such as fetching regional sales data and pushing it to a MySQL database.

```python
import schedule
import time
import datetime

def run_daily_etl():
    """Simulates an ETL process fetching data and updating a database."""
    current_time = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    print(f"[{current_time}] Starting ETL Pipeline...")
    # Code to extract, process, and load data goes here
    print(f"[{current_time}] ETL Pipeline completed successfully.")

def send_weekly_summary():
    print("Generating and emailing weekly visualisation reports...")

# Scheduling the tasks
schedule.every().day.at("06:00").do(run_daily_etl)
schedule.every().monday.at("09:00").do(send_weekly_summary)
schedule.every(4).hours.do(run_daily_etl) # Example of frequency-based scheduling

print("Scheduler is running. Press Ctrl+C to exit.")

# The script must be kept alive in a loop to continuously check the schedule
while True:
    schedule.run_pending()
    time.sleep(1) # Pause the loop for 1 second to prevent high CPU usage
```

### Limitations of `schedule`
The primary drawback of the `schedule` library is that the Python script must remain actively running in your terminal or IDE (like VS Code or Jupyter Lab). If the system restarts, or the terminal is closed, the schedule stops. For production-grade pipelines, we need OS-level scheduling.

## 2. Enterprise Scheduling with `cron` (Linux/macOS)

In an enterprise environment, your automated scripts will likely be deployed on a Linux server. `cron` is the standard time-based job scheduler in Unix-like operating systems. It runs as a background daemon, executing scripts at specified times regardless of whether a user is logged in.

### Understanding Cron Syntax
A cron job is defined by a specific syntax consisting of five time-and-date fields, followed by the command to execute.

```text
* * * * * command_to_execute
- - - - -
| | | | |
| | | | +----- Day of week (0 - 7) (Sunday is 0 or 7)
| | | +------- Month (1 - 12)
| | +--------- Day of month (1 - 31)
| +----------- Hour (0 - 23)
+------------- Minute (0 - 59)
```

**Examples:**
* `0 6 * * *` : Run every day at 6:00 AM.
* `0 9 * * 1` : Run every Monday at 9:00 AM.
* `*/15 * * * *` : Run every 15 minutes.

### Setting Up a Cron Job
To add or edit your scheduled jobs, you edit the `crontab` (cron table) file.

1. Open the terminal.
2. Type `crontab -e` to edit the file.
3. Add your scheduled job to the bottom of the file.

**Important Note on Environments:**
When `cron` runs a job, it does not load your standard environmental variables. Therefore, you must use **absolute paths** for both the Python executable (especially if using isolated environment managers like Anaconda) and the script itself.

```bash
# Example crontab entry using a specific Anaconda environment
0 6 * * * /home/user/anaconda3/envs/data_env/bin/python /home/user/projects/automation/daily_etl.py >> /home/user/projects/automation/logs/etl_log.txt 2>&1
```

*Notice the `>>` operator: This redirects standard output and errors (`2>&1`) to a log file, which is crucial since cron runs in the background without a visible terminal.*

## 3. The Windows Alternative: Task Scheduler

For local OS-level execution on a Windows machine, the native equivalent to `cron` is the **Windows Task Scheduler**. This is particularly useful for automating tasks locally without leaving a terminal window open.

### How to Schedule a Python Script in Windows:
1. Open **Task Scheduler** and click **Create Basic Task**.
2. Give the task a name (e.g., "Daily_Sales_ETL") and set the Trigger (e.g., Daily at 6:00 AM).
3. Set the Action to **Start a program**.
4. In **Program/script**, paste the absolute path to your Python executable (e.g., `C:\Users\Username\anaconda3\python.exe`).
5. In **Add arguments**, paste the absolute path to your Python script (e.g., `C:\Users\Username\Documents\projects\daily_etl.py`).
6. Save the task. It will now run autonomously in the background at the designated time.

## 4. Best Practices for Scheduled Automation

When moving from ad-hoc analysis to automated, scheduled pipelines, adherence to professional standards is vital:

1. **Always Implement Logging:** You will not be staring at the console when a 4:00 AM job fails. Use Python's built-in `logging` module to record successes, warnings, and errors to a specific local file.
2. **Handle Exceptions Gracefully:** Wrap your core execution logic in `try-except` blocks. If pulling data from a database fails due to network issues, the script should log the error and safely terminate, rather than crashing silently.
3. **Use Absolute Paths:** Whether handling local directories or navigating file systems with `os` and `shutil`, never assume the working directory. Always use absolute paths or dynamically resolve paths using `os.path.abspath(__file__)`.
4. **Environment Isolation:** Ensure the scheduled task explicitly calls the correct virtual environment where all required packages (like pandas, scikit-learn, openpyxl, sqlalchemy) are installed.
