# Text Cleaning and Preprocessing: Preparing Data for NLP

## Introduction
In the world of Natural Language Processing, the "Garbage In, Garbage Out" rule is absolute. Raw business text—whether it is customer support tickets, Amazon product reviews, or social media mentions—is inherently messy. It contains typos, emojis, URLs, HTML tags, and grammatical inconsistencies. 

Before we can extract insights or build machine learning models, we must standardize and clean this text. This phase is known as **Text Preprocessing**. It transforms human-readable text into a structured, uniform format that algorithms can digest.

---

## 1. Noise Removal and Regular Expressions (Regex)
The first step in any NLP pipeline is **Noise Removal**. Noise refers to any text that does not contribute to the meaning of the sentence for our specific analytical goal.

### Common Types of Noise:
* **HTML Tags & URLs:** Scraping web data often leaves `<br>` or `href` tags.
* **Special Characters & Punctuation:** Commas, exclamation marks, and symbols (unless you are specifically analyzing sentiment tied to punctuation, like "!!!").
* **Casing:** "Apple" and "apple" are treated as two entirely different words by computers unless converted to a standard case (usually lowercase).

### Using Regex for Cleaning
Regular Expressions (Regex) are powerful text-matching patterns used to identify and replace specific character sequences.

``` python
import re

def clean_business_text(text):
    # 1. Convert to lowercase
    text = text.lower()
    
    # 2. Remove URLs
    text = re.sub(r'http\S+|www\S+|https\S+', '', text, flags=re.MULTILINE)
    
    # 3. Remove HTML tags
    text = re.sub(r'<.*?>', '', text)
    
    # 4. Remove punctuation and numbers (keeping only alphabets)
    text = re.sub(r'[^a-z\s]', '', text)
    
    # 5. Remove extra whitespace
    text = text.strip()
    
    return text

raw_review = "Loved the product!!! <br> Check it out here: http://example.com. Bought 2 of them."
print(clean_business_text(raw_review))
# Output: "loved the product check it out here bought of them"
```

## 2. Tokenization
Once the text is clean, we need to break it down into manageable units. **Tokenization** is the process of splitting a string of text into smaller pieces, called *tokens*. Tokens are usually individual words, but they can also be sentences or sub-words.

* **Word Tokenization:** Splitting by words. ("Data Analytics is fun" -> `["Data", "Analytics", "is", "fun"]`)
* **Sentence Tokenization:** Splitting by sentences, useful for document-level summarization.

Tokens act as the foundational building blocks for all subsequent NLP steps, counting frequencies, and building vocabularies.

---

## 3. Stop-Words Removal
**Stop-words** are the most common words in a language (e.g., "the", "is", "in", "and", "to"). While crucial for human grammar, they carry very little unique information or "signal" for machine learning algorithms. 

In a business context, if you are trying to find out why a product is failing, the words "battery" and "overheating" are vital, whereas "the" and "it" are practically useless. Removing stop-words drastically reduces the size of your dataset and improves processing speed.

*Note: In advanced deep learning (like Transformers/LLMs), stop-words are often kept to preserve sentence context. However, for applied TF-IDF or basic sentiment analysis, removing them is standard practice.*

``` python
from nltk.corpus import stopwords
from nltk.tokenize import word_tokenize
import nltk

# Download stopwords if not already present
# nltk.download('stopwords')
# nltk.download('punkt')

text = "the new reporting dashboard is incredibly fast and efficient"
tokens = word_tokenize(text)

# Filter out english stop-words
stop_words = set(stopwords.words('english'))
filtered_tokens = [word for word in tokens if word not in stop_words]

print(filtered_tokens)
# Output: ['new', 'reporting', 'dashboard', 'incredibly', 'fast', 'efficient']
```

## 4. Stemming vs. Lemmatization
Text data often contains multiple variations of the same root word (e.g., "analyze", "analyzing", "analyzes"). Treating these as separate words dilutes the data. We use normalization techniques to reduce words to their base form. 

### A. Stemming
Stemming is a crude, rule-based approach that simply chops off the ends of words (prefixes/suffixes) to find the root.
* **Pros:** Very fast, computationally cheap.
* **Cons:** Often results in non-existent words (e.g., "Ponies" -> "Poni", "Organization" -> "Organ").
* **Algorithm:** Porter Stemmer or Snowball Stemmer.

### B. Lemmatization
Lemmatization is a sophisticated, dictionary-based approach. It considers the context and the Part-of-Speech (verb, noun, etc.) to convert the word back to its meaningful dictionary root, known as the *lemma*.
* **Pros:** Highly accurate, results in actual words (e.g., "Better" -> "Good", "Running" -> "Run").
* **Cons:** Slower, requires more computational overhead and built-in language dictionaries.

### Which one should a Data Analyst use?
For modern business applications, **Lemmatization is almost always preferred over Stemming**. The slight loss in processing speed is heavily outweighed by the improved accuracy and interpretability of the results, especially when presenting word clouds or topic summaries to stakeholders.

``` python
from nltk.stem import PorterStemmer, WordNetLemmatizer

stemmer = PorterStemmer()
lemmatizer = WordNetLemmatizer()

word = "better"

print(f"Stemming result: {stemmer.stem(word)}") 
# Output: better (Stemmer fails to map it to 'good')

print(f"Lemmatization result: {lemmatizer.lemmatize(word, pos='a')}") 
# Output: good ('pos=a' tells the lemmatizer the word is an adjective)
```

## Summary
A standard, applied text preprocessing pipeline for business data follows this flow:
1. **Ingest Data** -> 2. **Remove Noise/Regex** -> 3. **Lowercasing** -> 4. **Tokenization** -> 5. **Remove Stop-words** -> 6. **Lemmatization**.

Once the text is passed through this pipeline, the resulting tokens are clean, dense with meaning, and ready to be converted into numbers—which we will cover in the next module: **Text Vectorization and TF-IDF**.
