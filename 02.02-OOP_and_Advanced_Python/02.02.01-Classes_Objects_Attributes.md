# Object-Oriented Programming: Classes, Objects, and Attributes

## Overview
Object-Oriented Programming (OOP) is a programming paradigm that organizes software design around **data** (objects) rather than functions and logic. As your Python projects scale, OOP helps in managing complexity, reusing code, and modeling real-world entities accurately.

---

## 1. Core Concepts: Classes and Objects

### What is a Class?
A **Class** is a blueprint or a template for creating objects. It defines a set of attributes (variables) and methods (functions) that characterize any object instantiated from this class. 
* *Analogy:* A Class is like the architectural blueprint of a house.

### What is an Object?
An **Object** is an instance of a Class. Once a class is defined, you can create multiple objects from it, each with its own specific data.
* *Analogy:* If the class is the blueprint, the Object is the actual physical house built from that blueprint.

### Basic Syntax
To define a class in Python, use the `class` keyword followed by the class name (usually written in `PascalCase`).

```python
class Employee:
    # Class body goes here
    pass

# Creating objects (Instantiating)
emp1 = Employee()
emp2 = Employee()

print(type(emp1))  # Output: <class '__main__.Employee'>
```

---

## 2. Attributes: Class vs. Instance

Attributes are the variables that belong to a class or an object. Understanding the difference between Class Attributes and Instance Attributes is crucial.

### Class Attributes
These are variables defined directly inside the class body. They are shared across **all** instances (objects) of that class.

```python
class Employee:
    company = "Google"  # This is a class attribute

# Both objects share the same class attribute
emp1 = Employee()
emp2 = Employee()

print(emp1.company)  # Output: Google
print(emp2.company)  # Output: Google

# If we change the class attribute, it changes for all instances
Employee.company = "Alphabet"
print(emp1.company)  # Output: Alphabet
```

### Instance Attributes
These are variables that belong specifically to a single object. They are unique to each instance.

```python
class Employee:
    company = "Google"

emp1 = Employee()
emp1.name = "Animesh"     # Instance attribute specific to emp1
emp1.role = "Data Analyst"

emp2 = Employee()
emp2.name = "Rohan"       # Instance attribute specific to emp2

print(emp1.name)  # Output: Animesh
print(emp2.name)  # Output: Rohan
```

**Note on Precedence:** If an object has an instance attribute with the same name as a class attribute, the instance attribute takes priority when accessed through the object.

## 3. The `self` Parameter
When calling a method (a function inside a class) on an object, Python automatically passes the object itself as the first argument to the method. By convention, this parameter is named `self`.

```python
class Employee:
    company = "Google"
    
    # Defining a standard instance method (no decorator needed)
    def get_info(self):
        # 'self' refers to the object calling this method
        print(f"Employee {self.name} works at {self.company}")

emp = Employee()
emp.name = "Animesh"

# Python automatically translates this to Employee.get_info(emp)
emp.get_info()  
# Output: Employee Animesh works at Google
```

## 4. The `__init__` Method (Constructor)
Assigning instance attributes manually after creating an object is repetitive and prone to errors. Instead, we use the `__init__` method. 

The `__init__` method is a special "dunder" (double underscore) method, also known as a **constructor**. It is called automatically the exact moment an object is created.

```python
class Employee:
    company = "Google" # Class attribute
    
    # The Constructor
    def __init__(self, name, role, salary):
        # Setting instance attributes upon creation
        self.name = name
        self.role = role
        self.salary = salary
        print(f"Employee object created for {self.name}")

    def get_details(self):
        print(f"{self.name} is a {self.role} earning ${self.salary}.")

# Instantiating objects triggers the __init__ method automatically
emp1 = Employee("Animesh", "Data Analyst", 85000)
emp2 = Employee("Priya", "Data Scientist", 120000)

emp1.get_details()
# Output: Animesh is a Data Analyst earning $85000.
```

### Why is `__init__` so important?
1. **Ensures Data Integrity:** It forces you to pass the required data (like `name` and `role`) the moment the object is created, preventing objects from existing in an incomplete state.
2. **Cleaner Code:** It consolidates attribute assignment into a single block of code within the class template.

## 5. Object Introspection
Object introspection is the ability to examine an object's properties, methods, and metadata at runtime. Python provides built-in tools like `dir()` to list all attributes and methods available to an object, helping you explore and debug classes dynamically.

```Python
class Employee:
    company = "Google" # Class attribute
    
    # The Constructor
    def __init__(self, name, role, salary):
        # Setting instance attributes upon creation
        self.name = name
        self.role = role
        self.salary = salary
        print(f"Employee object created for {self.name}")

    def get_details(self):
        print(f"{self.name} is a {self.role} earning ${self.salary}.")

# Instantiating objects triggers the __init__ method automatically
emp1 = Employee("Animesh", "Data Analyst", 85000)

print(dir(emp1))
```
Output:-
```Plaintext
Employee object created for Animesh
['__class__', '__delattr__', '__dict__', '__dir__', '__doc__', '__eq__', '__format__', '__ge__', '__get__', '__getattribute__', '__gt__', '__hash__', '__init__', '__init_subclass__', '__le__', '__lt__', '__module__', '__ne__', '__new__', '__reduce__', '__reduce_ex__', '__getstate__', '__setstate__', '__str__', '__subclasshook__', 'company', 'get_details', 'name', 'role', 'salary']
```
- **Instance attributes**: `name`, `role`, and `salary` defined inside the constructor using `self`.
- **Class attributes**: `company` defined at the class level. 
- **Methods**: `get_details`.
- **Built-in/Magic attributes and methods (Dunder Method)**: Standard Python attributes like `__class__`, `__dict__`, `__doc__`, etc., that belong to all Python objects.

## 6. Magic (Dunder) Methods & Custom Class Behaviors
Magic methods, also called **dunder (double underscore) methods**, are special methods in Python that have double underscores at the beginning and end of their names (e.g., `__init__`, `__str__`, `__repr__`). They allow youeto define how your custom classes interact with built-in Python operators, functions, and language constructs, enabling clean operator overloading and Pythonic syntax.

### Why Data Analysts Use Dunder Methods:
When building custom data processing classes, utility wrappers, or machine learning pipelines, dunder methods allow your custom objects to behave like native Python data structures (like lists, dicts, or numbers).

* **Object Representation (`__str__` vs. `__repr__`):** Crucial for cleanly printing pipeline states or debugging logs.
* **Container Metrics (`__len__`):** Instantly return row counts or feature lengths from custom dataset wrapper classes.
* **Operator Overloading (`__add__`, `__sub__`, etc.):** Combine feature matrices or custom metric objects naturally using standard arithmetic symbols.

### Deep Dive: `__str__` vs. `__repr__` for Data Debugging
When building custom data classes, defining how objects are printed to the console is essential for debugging ETL scripts or machine learning outputs:
* **`__str__`:** Returns a human-readable, informal string representation. Used by `print()` and `str()`.
* **`__repr__`:** Returns an unambiguous, official string representation (ideally valid Python code to recreate the object). Used by the interactive interpreter and logging tracebacks.

```python
class DatasetBatch:
    def __init__(self, name, row_count):
        self.name = name
        self.row_count = row_count
 
    def __str__(self):
        return f"Dataset '{self.name}' containing {self.row_count:,} rows."  # Executive-friendly
 
    def __repr__(self):
        return f"DatasetBatch(name='{self.name}', row_count={self.row_count})"  # Developer/Debugging
 
batch = DatasetBatch("Olist_Transactions", 100000)

print(str(batch))    # Dataset 'Olist_Transactions' containing 100,000 rows.
print(repr(batch))   # DatasetBatch(name='Olist_Transactions', row_count=100000)
print(batch)         # Uses __str__ as default fallback for print()
````
_Best Practice:_ Always define at least `__repr__` for every custom class you create so that logging and debugging output is never ambiguous.

### Defining Container Behavior: `__len__`
The `__len__` method allows custom classes to integrate directly with Python's built-in `len()` function. This is especially useful when creating custom data loaders or batch iterators.
```Python
class FeatureStore:
    def __init__(self, features):
        self.features = features
 
    def __len__(self):
        # Returns the number of features tracked in the store
        return len(self.features)
 
store = FeatureStore(["age", "income", "credit_score", "tenure"])
print(len(store))  # Output: 4
```

## 7. Operator Overloading
Operator overloading is a feature in Python that allows you to give custom meanings to standard operators (like `+`, `-`, `*`, `==`) when used with user-defined objects.

By default, Python operators work natively with built-in data types like integers (`int`), floats (`float`), and strings (`str`). For example, `5 + 10` adds two numbers, and `"Hello " + "World"` concatenates two strings. However, if you try to use `+` directly between two custom class objects, Python will throw a `TypeError` because it doesn't know how to add them.

You can enable this by implementing **magic methods** (or dunder methods) inside your class.

### Common Magic Methods for Operators

| **Operator** | **Expression**            | **Magic Method**           |
| ------------ | ------------------------- | -------------------------- |
| `+`          | `obj1 + obj2`             | `__add__(self, other)`     |
| `-`          | `obj1 - obj2`             | `__sub__(self, other)`     |
| `*`          | `obj1 * obj2`             | `__mul__(self, other)`     |
| `/`          | `obj1 / obj2`             | `__truediv__(self, other)` |
| `==`         | `obj1 == obj2`            | `__eq__(self, other)`      |
| `!=`         | `obj1 != obj2`            | `__ne__(self, other)`      |
| `<`          | `obj1 < obj2`             | `__lt__(self, other)`      |
| `>`          | `obj1 > obj2`             | `__gt__(self, other)`      |
| `__str__`    | `str(obj)` / `print(obj)` | `__str__(self)`            |
| `__repr__`   | `str(obj)` / `print(obj)` | `__repr__(self)`           |
| `__len__`    | `len(obj)`                | `__len__(self)`            |

### Code Example: Overloading `+` and `*`
Imagine you are building a simulation program where you want to add employee salaries together or multiply their salaries by a performance bonus factor using standard arithmetic signs.
```Python
class Employee:
    company = "Google"
    
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary

    def __add__(self, other):
        # Overloading the '+' operator to add two employees' salaries together
        return self.salary + other.salary

    def __mul__(self, factor):
        # Overloading the '*' operator to multiply an employee's salary by a bonus multiplier
        return self.salary * factor

    def __str__(self):
        # Overloading string representation for cleaner printing
        return f"Employee: {self.name}, Salary: ${self.salary}"

# Creating employee objects
emp1 = Employee("Animesh", 85000)
emp2 = Employee("Priya", 120000)

# Using the overloaded '+' operator (Python internally calls emp1.__add__(emp2))
total_salary = emp1 + emp2
print(f"Total Combined Salary: ${total_salary}")  
# Output: Total Combined Salary: $205000

# Using the overloaded '*' operator (Python internally calls emp1.__mul__(1.10))
bonus_salary = emp1 * 1.10
print(f"Animesh's salary with a 10% bonus: ${bonus_salary}")  
# Output: Animesh's salary with a 10% bonus: $93500.0

# Using the overloaded '__str__' method
print(emp1)  
# Output: Employee: Animesh, Salary: $85000
```

### Why Use Operator Overloading?
1. **Intuitive Syntax:** It allows custom objects to interact using clean, standard mathematical and logical syntax instead of calling verbose custom functions (e.g., writing `emp1.add_salary(emp2)` vs simply `emp1 + emp2`). 
2. **Polymorphism:** It enables built-in functions and operators to work uniformly across different types of user-defined data structures.
