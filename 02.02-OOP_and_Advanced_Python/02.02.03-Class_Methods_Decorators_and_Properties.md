# Function Decorators, Static Methods, Class Methods & Properties

## Overview
In Python, **decorators** are a powerful feature used to wrap, modify, or enhance the behavior of functions and methods without altering their original source code. In data engineering and analysis, custom function decorators provide essential pipeline utilities—such as profiling, auditing, and caching. When building Object-Oriented Programming (OOP) architectures, Python's three core built-in decorators—`@staticmethod`, `@classmethod`, and `@property`—allow you to write cleaner, more encapsulated, and Pythonic code.

---

## 1. Function Decorators (Fundamentals & Data Pipeline Utilities)

A **Decorator** is a wrapper function that modifies or enhances another function's behavior without permanently altering its source code. Think of it as a quality control checkpoint, timer, or logger wrapped around your data functions.

In Python, functions are first-class objects—meaning they can be passed as arguments, returned from other functions, and assigned to variables.

### Why Data Professionals Need Custom Decorators:
* **Execution Profiling:** Measure how long a SQL query, API call, or Pandas aggregation takes.
* **Pipeline Auditing:** Log the number of rows/columns (`df.shape`) entering and leaving transformation steps.
* **API & Database Resiliency:** Automatically retry failed network requests or connection drops.
* **Caching Heavy Computations:** Prevent re-running expensive data loads during exploratory analysis.

### Core Mechanics: Wrapping Functions (`*args`, `**kwargs`)
To make a decorator work with *any* data pipeline function regardless of its inputs, use `*args` and `**kwargs` inside the `wrapper` function.
```python
import time
from functools import wraps
import pandas as pd

# 1. Custom Profiling Decorator
def measure_execution_time(func):
    """Logs the time taken by a data transformation or loading function."""
    @wraps(func)  # Preserves func.__name__ and docstrings
    def wrapper(*args, **kwargs):
        start_time = time.perf_counter()  # High-precision timer
        result = func(*args, **kwargs)
        end_time = time.perf_counter()
        print(f"⏱️ [{func.__name__}] Executed in {end_time - start_time:.4f} seconds.")
        return result
    return wrapper

# Applying the decorator to a simulated data task
@measure_execution_time
def process_data(records_count):
    # Simulating heavy data aggregation
    df = pd.DataFrame({"id": range(records_count), "value": range(records_count)})
    return df.groupby("value").sum()

# Triggering the decorated function
df_result = process_data(1_000_000)
````

### Advanced Data Use-Case: Pipeline Row-Tracker

In data pipelines, transformations can silently drop rows (e.g., inner joins, filters, `dropna`). This decorator acts as an automated audit trail for Pandas DataFrames.
```Python
from functools import wraps
import pandas as pd

def audit_dataframe(func):
    """Logs row and column shape changes caused by a DataFrame transformation."""
    @wraps(func)
    def wrapper(*args, **kwargs):
        # Search both positional args and keyword values for a DataFrame
        all_args = list(args) + list(kwargs.values())
        input_df = next((arg for arg in all_args if isinstance(arg, pd.DataFrame)), None)
        
        if input_df is not None:
            print(f"🔍 [Before {func.__name__}] Shape: {input_df.shape}")
        
        result_df = func(*args, **kwargs)
        
        if isinstance(result_df, pd.DataFrame):
            print(f"✅ [After {func.__name__}]  Shape: {result_df.shape}")
            
        return result_df
    return wrapper

# Example Pipeline Step
@audit_dataframe
def filter_active_users(df):
    return df[df['status'] == 'Active'].dropna()

# Testing the pipeline step
raw_data = pd.DataFrame({
    'user_id': [1, 2, 3, 4],
    'status': ['Active', 'Pending', 'Active', None]
})

clean_df = filter_active_users(raw_data)
```

### Built-in Essential Decorators for Data Science

You don't always need to build decorators from scratch. Python’s `functools` module offers built-in decorators tailored for data performance.

#### Storing Query Results (`@functools.lru_cache`)

Avoid hitting databases repeatedly for identical queries during active analysis:
```Python
from functools import lru_cache

@lru_cache(maxsize=32)
def run_expensive_sql_query(query_string):
    """Caches the output of a query. Consecutive calls with the same SQL string skip execution."""
    print(f"Fetching fresh data from DB for: '{query_string}'...")
    # Simulated query result
    return {"status": 200, "data": [1, 2, 3, 4, 5]}

# First run: Executes function logic
run_expensive_sql_query("SELECT * FROM sales WHERE year = 2026")

# Second run with same argument: Returns cached result instantly!
run_expensive_sql_query("SELECT * FROM sales WHERE year = 2026")
```
⚠️ **Data Analyst Note:** `@lru_cache` only works with **hashable (immutable)** arguments (like strings, integers, tuples). Do not pass mutable objects like Pandas `DataFrame`s, lists, or dicts into an `@lru_cache` decorated function, or Python will raise a `TypeError: unhashable type`.

## 2. Static Methods (`@staticmethod`)
By default, methods inside a class take the instance (`self`) as their first argument. However, sometimes you have a utility function that logically belongs inside a class because it relates to the class's purpose, but it doesn't actually need to access any instance attributes (`self`) or class attributes (`cls`).

We use the `@staticmethod` decorator for this. It behaves exactly like a regular Python function but is encapsulated within the class's namespace.

### Theoretical Key Points:
* Cannot modify object instance state.
* Cannot modify class state.
* Defined using the `@staticmethod` decorator.
* Does not take `self` or `cls` as the first parameter.

### Code Example
```python
class MathOperations:
    
    @staticmethod
    def add_numbers(x, y):
        """A simple utility method that doesn't need self or cls."""
        return x + y
        
    @staticmethod
    def is_workday(day):
        """Checks if a given date is a weekday."""
        if day.weekday() == 5 or day.weekday() == 6:
            return False
        return True

# Calling static methods directly on the class without instantiating it
sum_result = MathOperations.add_numbers(5, 10)
print(sum_result)  # Output: 15

import datetime
my_date = datetime.date(2026, 4, 21)
print(MathOperations.is_workday(my_date))  # Output: True
```

## 3. Class Methods (`@classmethod`)
While regular methods take the instance (`self`) as the first argument, **class methods** take the class itself as the first argument, conventionally named `cls`. 

Class methods are used **when you need to access or modify class-level variables (which affect all instances) rather than instance-level variables**. They are also widely used to create **"Alternative Constructors"** (methods that return an instance of the class in a different way than the standard `__init__` method).

### Theoretical Key Points:
* Can modify class state (changes apply to all instances of the class).
* Cannot modify specific instance state.
* Defined using the `@classmethod` decorator.
* Takes `cls` as the first parameter.

### Code Example
```python
class Employee:
    raise_amount = 1.04  # Class variable

    def __init__(self, first, last, pay):
        self.first = first
        self.last = last
        self.pay = pay

    @classmethod
    def set_raise_amt(cls, amount):
        """Modifies the class variable for ALL instances."""
        cls.raise_amount = amount

    @classmethod
    def from_string(cls, emp_str):
        """Alternative Constructor: creates an Employee from a hyphen-separated string."""
        first, last, pay = emp_str.split('-')
        return cls(first, last, int(pay))  # Returns a new instance of Employee

# Modifying class state using the class method
Employee.set_raise_amt(1.05)
print(Employee.raise_amount)  # Output: 1.05

# Using the alternative constructor to create an object
new_emp_1 = Employee.from_string("John-Doe-70000")
print(new_emp_1.first)  # Output: John
print(new_emp_1.pay)    # Output: 70000
```

## 4. Property Decorators (`@property`, Setters, and Deleters)
The `@property` decorator allows you to define a method that can be accessed exactly like an attribute. This is crucial for **Encapsulation**. 

Instead of creating explicit `get_value()` and `set_value()` methods (like you would in languages like Java or C++), Python allows you to use property decorators to hide complex logic (like validation or calculations) behind simple attribute access syntax.

### Theoretical Key Points:
* **`@property` (Getter):** Allows a method to be accessed without parentheses `()`. Computes values dynamically based on other attributes.
* **`@method_name.setter` (Setter):** Allows you to assign a value to that property, triggering custom logic or validation when an assignment is made.
* **`@method_name.deleter` (Deleter):** Defines specific behavior/cleanup logic when the `del` keyword is used on the property.

### Code Example
```python
class Employee:
    def __init__(self, first, last):
        self.first = first
        self.last = last

    @property
    def email(self):
        """Accessed as an attribute, computes email dynamically."""
        return f"{self.first.lower()}.{self.last.lower()}@company.com"

    @property
    def fullname(self):
        """Accessed as an attribute."""
        return f"{self.first} {self.last}"

    @fullname.setter
    def fullname(self, name):
        """Triggered when setting: emp.fullname = 'Jane Smith'"""
        first, last = name.split(' ')
        self.first = first
        self.last = last

    @fullname.deleter
    def fullname(self):
        """Triggered when deleting: del emp.fullname"""
        print('Delete Name logic triggered!')
        self.first = None
        self.last = None

# 1. Instantiating the class
emp_1 = Employee("Animesh", "Sanghi")

# 2. Accessing properties (Notice there are no parentheses!)
print(emp_1.fullname)  # Output: Animesh Sanghi
print(emp_1.email)     # Output: animesh.sanghi@company.com

# 3. Using the Setter
emp_1.fullname = "Kiran Sharma"
# The setter updates the underlying self.first and self.last
print(emp_1.first)     # Output: Kiran
print(emp_1.email)     # Output: kiran.sharma@company.com

# 4. Using the Deleter
del emp_1.fullname     # Output: Delete Name logic triggered!
print(emp_1.first)     # Output: None
```

### Practical Data Analytics Use Case: Pipeline Validation with `@property`
In data analytics and machine learning pipelines, you often need to configure parameters like confidence thresholds, batch sizes, or scaling limits. Using `@property` and setters ensures that invalid parameters (such as a confidence score greater than 1.0) are caught immediately before expensive transformations run.

```python
class PipelineConfig:
    def __init__(self, batch_size, confidence_threshold):
        self.batch_size = batch_size  # Uses the setter logic
        self._confidence_threshold = confidence_threshold

    @property
    def confidence_threshold(self):
        """Getter for confidence threshold."""
        return self._confidence_threshold

    @confidence_threshold.setter
    def confidence_threshold(self, value):
        """Setter with data validation logic for machine learning models."""
        if not (0.0 <= value <= 1.0):
            raise ValueError("Validation Error: Confidence threshold must be between 0.0 and 1.0.")
        print(f"Updating confidence threshold to: {value}")
        self._confidence_threshold = value

# Example usage in an analytics workflow
config = PipelineConfig(batch_size=1000, confidence_threshold=0.85)
print(f"Current Threshold: {config.confidence_threshold}")

# Attempting to set an invalid threshold triggers our custom validation error
try:
    config.confidence_threshold = 1.25
except ValueError as e:
    print(e)
````

> **Data Analyst Insight:** Encapsulation via `@property` prevents silent failures in automated ETL scripts by enforcing data contracts right at the object initialization phase.

## Practical Data Analytics Applications
While generic examples like `Dog` or `MathUtils` help explain syntax, data analysts apply instance, class, and static methods to solve real-world data pipeline and modeling challenges. Here is how these concepts apply directly to data analytics:

### 1. Class Methods (`@classmethod`) as Alternative Data Loaders (Factory Methods)
In data analytics, you often need to ingest data from different file formats (CSV, JSON, or SQL queries) into a structured analytical class. Class methods act as alternative constructors to instantiate data objects flexibly.
```python
import pandas as pd

class SalesDataset:
    def __init__(self, df, source_name):
        self.df = df
        self.source_name = source_name
        
    @classmethod
    from_csv(cls, filepath):
        """Alternative constructor to load data from a CSV file."""
        df = pd.read_csv(filepath)
        return cls(df, source_name=filepath)
        
    @classmethod
    from_json(cls, filepath):
        """Alternative constructor to load data from a JSON file."""
        df = pd.read_json(filepath)
        return cls(df, source_name=filepath)

# Usage: Instantiating the class using different factory methods
# sales_data = SalesDataset.from_csv("ecommerce_transactions.csv")
````

### 2. Static Methods (`@staticmethod`) for Data Validation Utilities
When building automated ETL pipelines, you frequently need standalone utility functions to validate incoming data formats (such as checking valid email structures or validating date ranges) before processing them in Pandas. Static methods group these utilities logically inside your data processing classes.
```Python
import re

class DataValidator:
    @staticmethod
    def validate_email(email):
        """Utility static method to check if an email string is valid."""
        pattern = r"^[\w\.-]+@[\w\.-]+\.\w+$"
        return bool(re.match(pattern, str(email)))

    @staticmethod
    def check_missing_threshold(df, threshold=0.3):
        """Validates if any column exceeds a missing value threshold."""
        missing_ratios = df.isnull().mean()
        return missing_ratios[missing_ratios > threshold].index.tolist()

# Usage: Can be called directly without instantiating the class
# invalid_cols = DataValidator.check_missing_threshold(df)
```

### 3. Property Decorators (`@property`) for Dynamic Metric Calculation
In financial or e-commerce analytics, metrics like **Profit** or **Profit Margin** depend dynamically on other columns (`Revenue` and `Cost`). Using `@property` allows you to compute these calculated columns on the fly without cluttering your raw dataframe memory.
```Python
class Transaction:
    def __init__(self, transaction_id, revenue, cost):
        self.transaction_id = transaction_id
        self.revenue = revenue
        self.cost = cost

    @property
    def profit(self):
        """Dynamically computes profit like a calculated column."""
        return self.revenue - self.cost

    @property
    def profit_margin(self):
        """Dynamically computes profit margin percentage."""
        if self.revenue == 0:
            return 0.0
        return (self.profit / self.revenue) * 100

# Usage: Accessed like regular attributes, but computed dynamically
# txn = Transaction("ORD-101", 500.0, 300.0)
# print(txn.profit)          # Output: 200.0
# print(txn.profit_margin)   # Output: 40.0
```

## Summary Comparison

| Decorator                 | First Argument | Scope of Access | Primary Use Case                                                                      |
| :------------------------ | :------------- | :-------------- | :------------------------------------------------------------------------------------ |
| **None (Regular Method)** | `self`         | Instance        | Modifying or accessing specific object data.                                          |
| **`@staticmethod`**       | `None`         | Independent     | Utility functions logically related to the class, but needing no class/instance data. |
| **`@classmethod`**        | `cls`          | Class Level     | Modifying class-level variables or creating Alternative Constructors.                 |
| **`@property`**           | `self`         | Attribute Style | Encapsulation, dynamic attribute calculation, Custom Getters, Setters, and Deleters.  |
