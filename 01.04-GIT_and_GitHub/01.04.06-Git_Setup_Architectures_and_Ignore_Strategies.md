# Git Architectures, System Setup & Enterprise Ignore Strategies

## 1. Version Control Architectures: CVCS vs. DVCS
Version control systems are categorized into two primary architectural models:

| Feature                  | Centralized Version Control (CVCS)                                  | Distributed Version Control (DVCS - Git)                                      |
| ------------------------ | ------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| **Primary Architecture** | Single centralized server housing total version history.<br><br>PDF | Every developer cloned repo contains full project history locally.<br><br>PDF |
| **Offline Capability**   | Limited; commits require server connectivity.<br><br>PDF            | Full offline support for commit, branch, and log inspection.<br><br>PDF       |
| **Risk Profile**         | Single point of failure if the server goes down.<br><br>PDF         | Redundant local copies safeguard against server data loss.<br><br>PDF         |
| **Examples**             | Subversion (SVN), Perforce.<br><br>PDF                              | Git, Mercurial.<br><br>PDF                                                    |

## 2. Multi-Platform Installation & Core Configuration

### Installation Commands
- **macOS (Homebrew):** 
```bash
 brew install git 
```

- **Linux (Debian/Ubuntu):** 
```bash
 sudo apt update && sudo apt install git -y 
```

- **Windows:** Download executable installer from [git-scm.com](https://git-scm.com/).

### System Configuration Setup
Run global identity settings post-installation:
```bash
# Configure user identity
git config --global user.name "Your Name" git config --global user.email "you@example.com"

# Set default code editor (e.g., VS Code)
git config --global core.editor "code --wait"

# Verify system configurations
git config --list 
```

## 3. Global & Project `.gitignore` Strategies for Data Science

### Global `.gitignore` Configuration
Configure a system-wide ignore file to suppress OS-generated files across all projects:
```bash
 git config --global core.excludesfile ~/.gitignore_global 
```

### Standard Data Science `.gitignore` Template
Create a `.gitignore` file in your project root to prevent tracking virtual environments, heavy data formats, and API keys:
```text
# ==========================================
# Environment & Secret Security
# ==========================================
.env *.env credentials.json secrets.yml

# ==========================================
# Python & Virtual Environments
# ==========================================
**pycache**/ *.py[cod] *$py.class .venv/ env/ venv/ ENV/

# ==========================================
# Data Science & Jupyter Artifacts
# ==========================================
.ipynb_checkpoints/ *-checkpoint.ipynb *.h5 *.pkl *.joblib *.parquet *.feather

# Large raw datasets (track metadata/scripts instead)
data/raw/* !data/raw/.gitkeep

# ==========================================
# OS & IDE Specific Files
# ==========================================
.DS_Store Thumbs.db .vscode/ .idea/ 
```

## 4. Remote Branch Operations
Managing remote repositories requires clean branch management on remote hosts (GitHub, GitLab, Bitbucket):
```bash
# List all remote branches
git branch -r

# Push local feature branch to remote and set tracking
git push -u origin feature/eda-pipeline

# Delete a branch from the remote repository
git push origin --delete feature/eda-pipeline

# Update local tracking references to remote state
git fetch --prune 
```
