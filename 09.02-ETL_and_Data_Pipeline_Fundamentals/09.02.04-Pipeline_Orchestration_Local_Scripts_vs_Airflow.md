# Pipeline Orchestration: Local Scripts vs. Apache Airflow

## Introduction
Building an ETL pipeline to process data and push it to a MySQL database is only half the battle. In a professional environment, data pipelines must run autonomously, reliably, and in a specific order. This is where **Orchestration** comes in. 

As a Data Analyst or Business Intelligence professional, ensuring that your data pipelines refresh on time is critical. If the underlying pipeline fails, the downstream Tableau or Power BI dashboards will display stale data, directly impacting business decisions. This capstone file compares simple local scheduling against enterprise-grade orchestration using Apache Airflow.

---

## 1. The Baseline: Local Script Orchestration (Cron & Task Scheduler)

When you first automate a script—such as a phase-based healthcare data redistribution algorithm—the easiest method is using the operating system's built-in tools:
* **Linux/macOS:** `cron`
* **Windows:** Task Scheduler

### How it Works
You point the system to your Python executable and the script, telling it to run at a specific interval (e.g., every day at 2:00 AM).

### The Limitations for Data Analytics
While local scheduling is great for simple automation, it falls short in enterprise environments:
* **Silent Failures:** If the Python script crashes (e.g., the MySQL server drops the connection), `cron` will not automatically alert you.
* **No Dependency Management:** If you have three scripts (Extract, Transform, Load) and the Extract script fails, `cron` will still try to run the Transform script, causing a cascade of errors.
* **No Historical Logging:** It is difficult to look back and analyse which runs succeeded, failed, or took unusually long.

---

## 2. Enterprise-Grade Orchestration: Apache Airflow

Apache Airflow is the industry standard for programmatic workflow orchestration. Instead of just running scripts on a timer, Airflow allows you to define workflows as code, manage dependencies, and monitor execution through a web interface.

### The Core Concept: DAGs (Directed Acyclic Graphs)
In Airflow, pipelines are defined as **DAGs**. 
* **Directed:** The tasks have a specific, one-way flow (e.g., Extract → Transform → Load).
* **Acyclic:** The pipeline does not loop back on itself; it has a clear start and end.
* **Graph:** A visual representation of tasks and their relationships.

### Why Analysts and Engineers Use Airflow:
1. **Robust Dependency Management:** You can set rules like, "Only run the Data Visualisation update if the MySQL database load was 100% successful."
2. **Automatic Retries:** If a web API times out during extraction, Airflow can automatically retry the task 3 times before sending a failure alert.
3. **Alerting:** Natively integrates with email (using `smtplib`) or Slack to notify you instantly if a pipeline breaks.

## 3. Comparison Breakdown

| Feature | Local Scripts (`cron`) | Apache Airflow |
| :--- | :--- | :--- |
| **Setup Complexity** | Very Low | High (requires local server or cloud deployment) |
| **Dependency Handling** | Poor (relies on time delays) | Excellent (Task A >> Task B) |
| **Error Retries** | Manual intervention required | Automated with custom parameters |
| **Monitoring & UI** | Terminal/Log files only | Rich Web UI with historical Gantt charts |
| **Best For...** | Solo projects, simple daily pulls | Enterprise BI, complex multi-stage ETL |

## 4. Capstone Implementation: Defining a Pipeline in Airflow

Below is an example of how you define an ETL pipeline in Airflow using Python. Notice how the tasks are clearly defined, and the dependencies are set at the very end.

```python
from airflow import DAG
from airflow.operators.python_operator import PythonOperator
from datetime import datetime, timedelta

# 1. Define default arguments (retries, alerting)
default_args = {
    'owner': 'data_team',
    'depends_on_past': False,
    'start_date': datetime(2026, 1, 1),
    'email': ['animeshsanghi.da@gmail.com'],
    'email_on_failure': True,
    'email_on_retry': False,
    'retries': 2,
    'retry_delay': timedelta(minutes=5),
}

# 2. Instantiate the DAG
dag = DAG(
    'healthcare_etl_pipeline',
    default_args=default_args,
    description='Extract, Transform, and Load healthcare data to MySQL',
    schedule_interval=timedelta(days=1),
)

# 3. Define the Python functions (The actual work)
def extract_data():
    print("Extracting data from source...")
    # Add extraction logic here

def transform_data():
    print("Applying phase-based redistribution algorithm...")
    # Add pandas processing logic here

def load_data():
    print("Pushing processed data to MySQL...")
    # Add SQLAlchemy/MySQL logic here

# 4. Create the Airflow Tasks
task_extract = PythonOperator(
    task_id='extract_raw_data',
    python_callable=extract_data,
    dag=dag,
)

task_transform = PythonOperator(
    task_id='transform_clean_data',
    python_callable=transform_data,
    dag=dag,
)

task_load = PythonOperator(
    task_id='load_to_mysql',
    python_callable=load_data,
    dag=dag,
)

# 5. Define the Dependencies (The Orchestration)
task_extract >> task_transform >> task_load
```
