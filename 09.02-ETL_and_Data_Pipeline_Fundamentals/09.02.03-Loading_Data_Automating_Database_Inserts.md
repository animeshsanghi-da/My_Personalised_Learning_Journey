# ETL Pipelines: Loading Data and Automating Database Inserts

## Introduction
The final stage of the ETL (Extract, Transform, Load) pipeline is arguably the most critical for production systems. After you extract raw data and transform it using Pandas to clean and analyse it, you must securely and efficiently load it into a destination database. 

In this module, we will move away from manual CSV exports and focus on programmatic database interactions using Python and MySQL. We will cover secure connections, optimising bulk inserts, and structuring complex phase-based loading scripts—such as those used for redistribution algorithms.

---

## 1. Secure Database Connections with SQLAlchemy

While libraries like `mysql-connector-python` are great for simple queries, **SQLAlchemy** is the industry standard for data pipelines. It acts as an Object Relational Mapper (ORM) and manages database connection pooling efficiently. 

Never hardcode your credentials in your main script. Use environment variables or a secure configuration file.

```python
import pandas as pd
from sqlalchemy import create_engine
import os

# Securely fetching credentials from environment variables
DB_USER = os.getenv('DB_USER', 'root')
DB_PASS = os.getenv('DB_PASS', 'your_password')
DB_HOST = os.getenv('DB_HOST', 'localhost')
DB_NAME = os.getenv('DB_NAME', 'analytics_db')

# Create the SQLAlchemy engine for MySQL
# Format: mysql+pymysql://<username>:<password>@<host>/<dbname>
connection_string = f"mysql+pymysql://{DB_USER}:{DB_PASS}@{DB_HOST}/{DB_NAME}"
engine = create_engine(connection_string)

print("Database engine created successfully.")
```

## 2. Optimising Bulk Inserts

When dealing with large datasets, inserting row-by-row is computationally expensive and slow. Pandas provides the `.to_sql()` method, but for pipeline efficiency, you must leverage chunking and multi-row inserts.

```python
def load_data_to_mysql(df, table_name, engine):
    """
    Loads a Pandas DataFrame into a MySQL database efficiently.
    """
    try:
        # if_exists='append' ensures we don't drop the table, just add to it.
        # chunksize=1000 breaks large dataframes into manageable batches.
        # method='multi' allows multiple rows to be passed in a single INSERT statement.
        
        df.to_sql(
            name=table_name, 
            con=engine, 
            if_exists='append', 
            index=False,
            chunksize=1000,
            method='multi'
        )
        print(f"Successfully loaded {len(df)} rows into '{table_name}'.")
        
    except Exception as e:
        print(f"Error loading data: {e}")
```

## 3. Phase-Based Loading and Data Redistribution Algorithms

In real-world business scenarios, ETL is rarely a simple A-to-B move. Often, data must be processed in distinct phases, especially when dealing with complex logic like healthcare data redistribution (e.g., reallocating medical supplies or patient loads across different wards or facilities based on capacity).

Structuring your Python script into distinct phases ensures that your algorithm can validate the transformations before pushing anything to MySQL.

### Example: Phase-Based Healthcare Redistribution Pipeline

```python
def phase_one_extract_and_clean(file_path):
    """Phase 1: Ingest raw healthcare logs and standardise formats."""
    df = pd.read_csv(file_path)
    # Standardise column names and drop missing critical values
    df.columns = [col.strip().lower().replace(' ', '_') for col in df.columns]
    df.dropna(subset=['facility_id', 'patient_count'], inplace=True)
    return df

def phase_two_redistribution_algorithm(df):
    """Phase 2: Apply business logic to calculate resource redistribution."""
    # Example logic: Flag facilities over 80% capacity for redistribution
    capacity_threshold = 0.80
    df['utilisation_rate'] = df['patient_count'] / df['total_beds']
    
    # Create a new column to determine required transfers
    df['redistribution_status'] = df['utilisation_rate'].apply(
        lambda x: 'Requires Transfer' if x > capacity_threshold else 'Stable'
    )
    
    # Filter only the records that need database updates
    redistribution_df = df[df['redistribution_status'] == 'Requires Transfer'].copy()
    return redistribution_df

def phase_three_database_load(df, engine):
    """Phase 3: Push the calculated redistribution data to MySQL."""
    print("Initiating Phase 3: Database Load...")
    load_data_to_mysql(df, 'healthcare_redistribution_queue', engine)

# --- Master Execution Block ---
if __name__ == "__main__":
    # 1. Extract
    raw_data = phase_one_extract_and_clean('daily_hospital_logs.csv')
    
    # 2. Transform (Algorithm)
    actionable_data = phase_two_redistribution_algorithm(raw_data)
    
    # 3. Load
    if not actionable_data.empty:
        phase_three_database_load(actionable_data, engine)
    else:
        print("No redistribution required today. Pipeline executed successfully.")
```

## 4. Best Practices for Production 

1. **Idempotency:** Your pipeline should be able to run multiple times without duplicating data in MySQL. Use primary keys and `UPSERT` logic (or staging tables) if necessary.
2. **Logging:** Always track the number of rows read vs. rows written. If your script processes 10,000 rows but only inserts 9,990, you need logs to analyse where the 10 rows were dropped.
3. **Connection Closure:** While SQLAlchemy engines manage connection pools automatically, ensure you handle exceptions gracefully so database ports are not left hanging during a crash.
