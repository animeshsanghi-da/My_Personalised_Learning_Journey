# Best Practice: Securing Database Connections

## Overview

When building production-level applications, you should never hardcode your database passwords directly into your scripts. Additionally, if your project has multiple files (e.g., one for scraping, one for cleaning, one for analytics), copying and pasting the database connection logic violates the DRY (Don't Repeat Yourself) principle.

The industry standard is to store sensitive credentials in a hidden `.env` (environment) file and create a central `utils.py` file to handle the connection logic. 

## 1. Setting up the .env File

Create a new file in your project folder named exactly `.env`. This file stores your secret variables. **Important:** Always add `.env` to your `.gitignore` file so you don't accidentally upload your password to GitHub!

``` env
# .env
DB_PASSWORD=your_super_secret_password
```

## 2. Creating the Connection Utility (utils.py)

Create a file named `utils.py`. Here are the different approaches you can take, ranging from basic to advanced.

### Option A: Hardcoding the Password (Not Recommended)
Creates an engine using the password written directly in the code.

``` python
from sqlalchemy import create_engine

def get_db_connection(db_name="company_db"):
    db_user, db_host = "root", "localhost"
    db_password = "your_password"
    engine = create_engine(f"mysql+pymysql://{db_user}:{db_password}@{db_host}/{db_name}")
    return engine
```

### Option B: Manual Password Entry (Using `getpass`)
Uses the `getpass` library to establish a secure connection by prompting the user in the terminal.

``` python
import getpass
from sqlalchemy import create_engine

def get_db_connection(db_name="company_db"):
    db_user, db_host = "root", "localhost"
    db_password = getpass.getpass("Enter DB Password: ")  # Fetches password securely
    engine = create_engine(f"mysql+pymysql://{db_user}:{db_password}@{db_host}/{db_name}")
    return engine
```

### Option C: Using Environment Variables (`dotenv`)
Uses the `python-dotenv` library (`pip install python-dotenv`) alongside `os` to securely load the password from your `.env` file.

``` python
import os
from sqlalchemy import create_engine
from dotenv import load_dotenv

def get_db_connection(db_name="company_db"):
    db_user, db_host = "root", "localhost"
    load_dotenv()
    db_password = os.getenv("DB_PASSWORD") # Fetches password from .env file 
    engine = create_engine(f"mysql+pymysql://{db_user}:{db_password}@{db_host}/{db_name}")
    return engine
```

### Option D: The Ultimate Hybrid Approach (Recommended)
Combines both concepts for a robust connection. It first tries to fetch the password from the `.env` file. If the `.env` file is missing, it includes a smart fallback mechanism to securely prompt the user in the terminal. [Ready to use utility.py file](Learning_path_fully_optimised/99.99-Shared_Utilities/utils.py).

``` python
import os
import getpass
import logging
from sqlalchemy import create_engine
from sqlalchemy.exc import SQLAlchemyError
from dotenv import load_dotenv

logging.basicConfig(level=logging.INFO, format='%(levelname)s: %(message)s')

def get_db_connection(db_name="company_db"):
    db_user, db_host = "root", "localhost"
    
    # Attempt 1: Load from .env securely
    load_dotenv()
    db_password = os.getenv("DB_PASSWORD")
    
    # Attempt 2: Fallback to manual terminal prompt
    if not db_password:
        logging.warning("No .env file found. Manual entry required.")
        db_password = getpass.getpass("Enter DB Password: ")
        
    # Retry Loop: Allows up to 3 connection attempts
    for attempt in range(3):
        try:
            engine = create_engine(f"mysql+pymysql://{db_user}:{db_password}@{db_host}/{db_name}")
            with engine.connect():
                logging.info("Database connected successfully.")
            return engine
        except SQLAlchemyError:
            if attempt < 2:
                logging.error("Access Denied. Try again.")
                db_password = getpass.getpass("Enter DB Password: ")
            else:
                logging.error("Max attempts reached. Connection failed.")
                return None
```

## 3. How to Use It in Your Main Code

Now, in any other script where you need database access, your code remains clean, short, and highly secure.

``` python
# main_analytics.py
import pandas as pd
from utils import get_db_connection

engine = get_db_connection("company_db")
query = "SELECT * FROM sales_data"

df = pd.read_sql(query, engine)
print(df)
```

## Summary & Best Practices

1. **Never commit `.env` files:** Always ensure `.env` is listed inside your `.gitignore` file.
2. **Modularize your code:** Writing functions like `get_db_connection` in an external utility file keeps your main analytics scripts clean and focused on data, not configuration.
3. **Handle failures gracefully:** The 3-attempt loop ensures that a simple typo doesn't immediately crash a larger automated script.
