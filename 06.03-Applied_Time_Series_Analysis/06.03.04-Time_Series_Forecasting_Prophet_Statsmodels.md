## 1. Setting the Baseline: ARIMA with Statsmodels

Before deploying complex algorithms, it is best practice to establish a statistical baseline. **ARIMA** (AutoRegressive Integrated Moving Average) is a classic model used to forecast a time series based on its own past values.

* **AR (AutoRegressive):** Uses the dependent relationship between an observation and a number of lagged observations.
* **I (Integrated):** Differencing raw observations to make the time series stationary.
* **MA (Moving Average):** Uses the dependency between an observation and a residual error from a moving average model.

### 1.1 The Statsmodels Implementation

Here is how you can build a baseline ARIMA model using `statsmodels` on a daily sales dataset.

``` python
import pandas as pd
import matplotlib.pyplot as plt
from statsmodels.tsa.arima.model import ARIMA
from sklearn.metrics import mean_absolute_error, mean_squared_error
import numpy as np

# 1. Load and prepare data
# Assuming 'df' is your pre-processed dataframe with a DatetimeIndex
# and a column 'daily_sales'
train_data = df.iloc[:-30] # Train on all but the last 30 days
test_data = df.iloc[-30:]  # Test on the last 30 days

# 2. Define and fit the ARIMA model
# Order (p, d, q) requires tuning based on ACF/PACF plots
# Here we use (5, 1, 0) as a baseline example
model = ARIMA(train_data['daily_sales'], order=(5, 1, 0))
fitted_model = model.fit()

# 3. Forecast the next 30 days
forecast = fitted_model.forecast(steps=30)

# 4. Evaluate the Baseline
mae = mean_absolute_error(test_data['daily_sales'], forecast)
rmse = np.sqrt(mean_squared_error(test_data['daily_sales'], forecast))
print(f"ARIMA Baseline MAE: {mae:.2f} | RMSE: {rmse:.2f}")
```

While ARIMA is powerful mathematically, it struggles with missing data, extreme outliers (common in business sales), and complex multiple seasonalities. This is where Prophet comes in.

## 2. Scaling Business Forecasts with Meta's Prophet

Developed by Meta (Facebook), **Prophet** is designed specifically for forecasting business time series data. It excels where traditional statistical models fall short:
1.  **Flexibility:** Automatically handles daily, weekly, and yearly seasonality.
2.  **Robustness:** Highly resilient to missing data and large outliers.
3.  **Business Logic:** Natively incorporates holiday effects (crucial for retail and e-commerce).

### 2.1 Formatting Data for Prophet
Prophet is strict about column names. Your dataframe must have exactly two columns:
* `ds`: The datetime column (Datestamp).
* `y`: The target metric to forecast (Numeric).

``` python
from prophet import Prophet

# 1. Format the dataframe for Prophet
prophet_df = df.reset_index()[['date', 'daily_sales']]
prophet_df.columns = ['ds', 'y'] # Renaming to match Prophet's requirements

# Display the formatted data
print(prophet_df.head())
```

### 2.2 Building and Visualising the Prophet Model

Prophet treats forecasting as a curve-fitting task rather than a traditional time-step simulation, making it incredibly fast.

``` python
# 2. Initialize and fit the Prophet model
m = Prophet(
    yearly_seasonality=True,
    weekly_seasonality=True,
    daily_seasonality=False # Set to True only if you have sub-daily (hourly) data
)
m.fit(prophet_df)

# 3. Create a future dataframe for the next 90 days
future = m.make_future_dataframe(periods=90)

# 4. Predict the future values
forecast = m.predict(future)

# 5. Visualise the forecast
fig1 = m.plot(forecast)
plt.title("90-Day Revenue Forecast using Prophet")
plt.show()

# 6. Visualise the individual components (Trend, Weekly, Yearly)
fig2 = m.plot_components(forecast)
plt.show()
```

*Business Insight:* The `plot_components` function is invaluable for business stakeholders. It instantly visualises which day of the week drives the most sales and which months represent the peak season, directly informing marketing and operational strategies.

## 3. Advanced Business Context: Holiday Effects

In retail and e-commerce, holidays create massive spikes in data that confuse standard models. Prophet allows you to add built-in country holidays to explain these spikes, preventing the model from misinterpreting a Diwali or Black Friday sale as a permanent upward trend.

``` python
# Initialise the model with holiday awareness
m_holidays = Prophet()

# Add country-specific holidays (e.g., India or Brazil based on your dataset)
m_holidays.add_country_holidays(country_name='IN') # 'BR' for Brazil (Olist data)

m_holidays.fit(prophet_df)

# Check which holidays were included
print(m_holidays.train_holiday_names)
```

## 4 Beyond Linear Approaches — Tree-Based Forecasting

While Prophet and ARIMA are excellent for trend and seasonality, they often struggle when you need to incorporate **exogenous variables** (external factors like price changes, marketing spend, or stock availability). Tree-based models, such as **XGBoost**, treat time series as a supervised regression problem.

### 4.1 Turning Time into Features

To use a machine learning model, we "reframe" the time series. We convert the `daily_sales` column into a set of inputs ($X$) and outputs ($y$) using **feature engineering** (creating lags and rolling windows):
```Python
# Create lag features: e.g., 'What were sales 1 day ago?'
df['lag_1'] = df['daily_sales'].shift(1)
df['lag_7'] = df['daily_sales'].shift(7)

# Create rolling window features: e.g., 'Moving average of the last 7 days'
df['rolling_mean_7'] = df['daily_sales'].shift(1).rolling(window=7).mean()

# Drop rows with NaN values created by shifting
df = df.dropna()
```

### 4.2 The Machine Learning Approach

Once the data is structured, you can use any regressor. Unlike Prophet, these models do not care about time until you explicitly give them features like `day_of_week` or `month`.
```Python
from xgboost import XGBRegressor

# Define features (X) and target (y)
features = ['lag_1', 'lag_7', 'rolling_mean_7']
X = df[features]
y = df['daily_sales']

# Split: Do NOT use random split! Use a time-based split.
split_idx = int(len(df) * 0.8)
X_train, X_test = X.iloc[:split_idx], X.iloc[split_idx:]
y_train, y_test = y.iloc[:split_idx], y.iloc[split_idx:]

# Train and Predict
model = XGBRegressor(n_estimators=100)
model.fit(X_train, y_train)
predictions = model.predict(X_test)
```
> **Why use this over Prophet?**
> 
> Use **Prophet** when you have a clean dataset, holidays, and need a quick, explainable business report. Use **XGBoost/Random Forest** when you have a dataset with many "features" (e.g., promotional status, competitor pricing, weather) and you need higher accuracy.

### Summary of Methodologies for Your Pipeline

| **Methodology** | **Best For**          | **Pros**                                            | **Cons**                                            |
| --------------- | --------------------- | --------------------------------------------------- | --------------------------------------------------- |
| **ARIMA**       | Statistical Baselines | Mathematically rigorous; no training data needed.   | Poor at handling holidays; hard to scale.           |
| **Prophet**     | Business Forecasting  | Fast; handles missing data & holidays; explainable. | Can be "too smooth" for highly volatile data.       |
| **Tree-Based**  | Complex Drivers       | Excellent with external factors/features.           | Requires manual feature engineering (lags/windows). |

## 5. Evaluating the Forecast (Cross-Validation)

To prove to stakeholders that your model is reliable, you must evaluate its historical accuracy. Prophet includes built-in cross-validation tailored for time series.

``` python
from prophet.diagnostics import cross_validation, performance_metrics

# Perform cross-validation: 
# Train on initial 365 days, then make 30-day forecasts every 180 days
df_cv = cross_validation(m, initial='365 days', period='180 days', horizon='30 days')

# Calculate performance metrics
df_p = performance_metrics(df_cv)

# Display Mean Absolute Percentage Error (MAPE)
print(df_p[['horizon', 'rmse', 'mae', 'mape']].head())
```

**Understanding the Metrics:**
* **MAE (Mean Absolute Error):** On average, how many units/dollars is our forecast off by?
* **RMSE (Root Mean Squared Error):** Penalises large forecasting errors heavily.
* **MAPE (Mean Absolute Percentage Error):** The easiest metric to communicate to business leaders (e.g., "Our model is accurate within a 5% margin of error").
