# Time Series: Datetime Fundamentals and Indexing

## Introduction
In business analytics, time is one of the most critical dimensions. Whether you are evaluating daily transaction records for a quick-service restaurant, analysing seasonal trends in e-commerce, or forecasting intercity logistics, raw data is almost always timestamped. 

Python’s `pandas` library offers incredibly robust tools for time series analysis. This module will walk you through parsing messy date strings into machine-readable objects, setting up a datetime index, handling regional time zones, and efficiently slicing data to generate business reports.

---

## 1. Parsing Dates with `pd.to_datetime()`
Often, data imported from CSV files or SQL databases treats dates as simple strings (objects). Before performing any time-based operations, these must be converted into native Pandas datetime objects.

Let's simulate a business dataset tracking daily revenue.

``` python
import pandas as pd
import numpy as np

# Simulating raw business transaction data
data = {
    'transaction_date': ['10-11-2023', '27-11-2023', '02-01-2024', '30-01-2024', '14-05-2025'],
    'revenue_inr': [4500, 5200, 4800, 6100, 5900],
    'store_location': ['Indore', 'Shivpuri', 'Indore', 'Indore', 'Shivpuri']
}

df = pd.DataFrame(data)

# Check initial data types
print("Before Conversion:")
print(df.dtypes)

# Convert string to datetime
# Format specifies how the string is currently structured (Day-Month-Year)
df['transaction_date'] = pd.to_datetime(df['transaction_date'], format='%d-%m-%Y')

print("\nAfter Conversion:")
print(df.dtypes)
```

### Why does the format matter?
If you do not specify the `format` or use `dayfirst=True`, Pandas might misinterpret `02-01-2024` as February 1st instead of January 2nd, which can severely skew quarterly reporting.

## 2. Setting a Datetime Index
By default, DataFrames use a numeric index (0, 1, 2...). In time series analysis, it is a best practice to set the datetime column as the index. This unlocks powerful time-based slicing and resampling functions.

``` python
# Set the transaction_date as the index
df.set_index('transaction_date', inplace=True)

# Sort the index chronologically (crucial for time series operations)
df.sort_index(inplace=True)

print(df.head())
```

*Note: Running this directly in Jupyter Lab or VS Code will visually format the index on the left-hand side of your DataFrame output, distinguishing it from standard columns.*

---

## 3. Subsetting and Slicing Time Periods
Once your DataFrame has a sorted datetime index, filtering data for business reporting becomes incredibly intuitive. You no longer need complex boolean masking; you can simply pass strings to `.loc[]`.

``` python
# 1. Select a specific year (e.g., all 2024 transactions)
sales_2024 = df.loc['2024']

# 2. Select a specific month and year (e.g., January 2024)
jan_2024 = df.loc['2024-01']

# 3. Slice a specific date range (e.g., Nov 2023 to Jan 2024)
q4_to_q1_sales = df.loc['2023-11-01':'2024-01-31']

print("Sales from Nov 2023 to Jan 2024:")
print(q4_to_q1_sales)
```

This indexing approach is heavily optimised under the hood by Pandas, making it highly efficient even when querying millions of rows.

## 4. Handling Time Zones (UTC to IST)
Modern applications and cloud databases typically store timestamps in UTC (Coordinated Universal Time) to maintain consistency. However, for regional operations and reporting, these timestamps must be converted to local time zones.

``` python
# Creating a sample series with UTC timestamps
utc_times = pd.Series([
    pd.Timestamp('2024-04-12 08:30:00'), 
    pd.Timestamp('2024-04-14 12:45:00')
])

# Step 1: Localize the naive timestamps to UTC
utc_times = utc_times.dt.tz_localize('UTC')

# Step 2: Convert to Indian Standard Time (Asia/Kolkata)
ist_times = utc_times.dt.tz_convert('Asia/Kolkata')

print("Original UTC Times:")
print(utc_times)
print("\nConverted IST Times:")
print(ist_times)
```

### The Business Impact
Failing to convert UTC to the correct local time zone can result in transactions being assigned to the wrong business day. For example, a purchase made at 2:00 AM IST on Tuesday will appear as 8:30 PM UTC on Monday, completely altering daily revenue metrics.
